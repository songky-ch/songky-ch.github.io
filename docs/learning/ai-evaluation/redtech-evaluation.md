# 小红书评测 Agent: 从推荐现场到测试任务证据

本文带读小红书技术 REDtech 的《小红书推荐系统评测 Agent: 上下文驱动的 LLM-as-Judge 实践》, 并把可迁移的机制接入专项测试助手的学习案例. 目标是理解评测单元、证据边界、规则与模型分工、校准、回放及实验诊断, 不是复刻小红书内部平台.

## 1. 先辨清: 用 Agent 评测业务, 与评测 Agent 自身

原文第 3-4 页说明: 点击、停留等行为统计可以观察用户反应, 却不能直接说明推荐内容怎样改变. 语义评测补充内容侧的诊断, 不代替真实行为实验. 同样的点击率可能对应不同的内容组合; 内容结构更好也不自动推出点击率提升.

在我们的测试场景中, 可以把这个区分迁移为两条链:

- 业务效果: 测试计划是否帮助发现缺陷、减少人工时间, 需要真实测试与业务记录.
- 内容与执行证据: 用例是否覆盖需求、是否可执行, Agent 是否遵守授权, 用独立评分和环境断言检查.

“评测 Agent”是组织材料、调度评分器和保存结果的应用. 它并不意味着评分标准由模型随意发明, 也不意味着必须采用多 Agent. 被评对象可以是推荐列表、RAG 答案或测试计划, 但三者不能共用未经定义的“准确率”.

![原文评测单元与项目迁移边界](/images/redtech-evaluation/context.svg)

读图时先确定一次请求的边界. 原文的三项信息改变任意一项, 样本语境就变了; 迁移后必须明确哪些测试环境、需求和工具结果属于同一次任务, 不能只保存最后一段回答.

## 2. 原文如何定义一个评测样本

第 5-6 页将样本围绕用户当时的状态、请求发生时间及按原顺序展示的内容组织. 用户状态包含长期兴趣与近期消费; 时间影响内容有效性; 顺序与完整列表影响重复、集中和整体体验. 实验目标另外说明这次策略想验证什么.

原文同时保留单篇、列表和请求层的结果. 上下文缺失、获取失败与没有请求某项材料需要区分, 不允许模型把缺失事实编出来. 这是一项数据契约要求, 不是“给 Prompt 塞更多字段”.

**项目迁移, 非小红书原始 schema:** 一次专项测试任务的快照应包含需求版本、允许环境、任务目标、原问题、改写候选、文档解析版本、按顺序的工具观测、计划版本和产物引用. 时间应是任务实际执行时刻; 不用今天的接口文档替代当时版本后还声称在重放同一个现场.

```json
{
  "snapshot_id": "synthetic-task-01",
  "requirement_version": "r3",
  "environment": "test",
  "request_time": "2026-10-28T08:00:00+08:00",
  "ordered_observations": ["doc-read-1", "tool-result-2"],
  "artifact_refs": ["cases-v1"],
  "evaluation_version": {
    "rubric": "rubric-v1",
    "rules": "rules-v1",
    "prompt": "judge-p1",
    "model": "synthetic-no-model",
    "input_selection": "selection-v1"
  }
}
```

这是合成契约示例, 不可直接当作生产字段规范. 凭证不进入公开快照; 生产快照还需要访问控制、保留期限和删除机制.

## 3. 分维度评分, 不让总分掩盖问题

原文第 8-10 页将基础体验与实验目标分开. 内容质量关注内容本身, 时效判断需要请求时间, 兴趣匹配依赖用户状态, 多样性需要完整有序列表; 目标符合度检查策略希望改变的内容特征是否出现. 改善目标不等于没有体验代价.

原文语义维度使用 0/1/2 三档, 每一档由对应评分标准定义. 结果携带分数、理由与执行状态; 综合分可辅助筛选, 但诊断要回到分项. 原文允许任务设置门控条件, 不让其他维度高分抵消明确不可接受的问题. 它没有公开可供照搬的统一评分阈值与通用权重.

| 原文概念 | 测试助手中的迁移 | 不应机械照搬 |
| --- | --- | --- |
| 单篇内容质量 | 单条用例有明确步骤、断言和来源 | 不能用文案流畅度代替测试可执行性 |
| 时效性 | 需求、接口、环境及引用版本适用 | 文档发布时间近不代表业务事实正确 |
| 兴趣匹配 | 产物是否回应本次任务目标和角色需要 | 不把用户偏好当作业务事实 |
| 列表多样性 | 用例集合的风险覆盖与冗余 | 用例越“多样”不必然覆盖关键风险 |
| 目标符合度 | 本次优化是否提升指定风险覆盖 | 覆盖提升不能抵消越权执行 |

## 4. 规则、统计特征与模型怎样分工

第 7、11-12 页展示了上下文准备、配置解析、分维度执行及聚合链路. 对可由结构化字段确定的事实, 代码直接计算. 可稳定统计但仍需语境解释的信息, 先计算特征再交给模型. 依赖用户、内容与策略语境的问题, 由受约束的语义裁判判断. 确定性结论不应被一个综合模型回答覆盖.

![证据到规则和语义评分的分流](/images/redtech-evaluation/routing.svg)

图中的三条路是按证据性质分工, 不表示任一维度都必须先调用一次模型. 例如测试环境是否为 test、工具是否在允许集合内, 可直接用规则; “用例是否理解了异常流程”才需要需求证据与语义判定.

原文还强调, 曝光后的真实点击、停留、互动及反馈作为独立链路输入, 不参与语义评分, 只在分析时对齐. 对我们而言, 可以先隐藏人工验收标签和目标版本名, 再让裁判评分, 避免将答案标签泄漏进被测或裁判输入. 这是迁移思路, 不是说所有评测任务都禁止提供参考答案: 参考答案是否提供, 必须由具体评分契约定义.

## 5. 分数之外还必须保存状态

原文区分材料是否齐全、执行是否成功与业务判断. 下表是我们为了演示设计的状态编码, 并非声称原文使用这些枚举:

| 状态 | 分数 | 处理 |
| --- | --- | --- |
| scored | 0、1 或 2 | 按 rubric 解读, 0 是有效的差评 |
| missing_context | null | 未取得必要材料, 不能冒充 0 分 |
| acquisition_error | null | 获取工具失败, 与材料本来不存在分开 |
| judge_error | null | 裁判超时或输出不合法, 保存原观测再重评 |
| not_requested | null | 本次没有请求这个可选维度 |

聚合应同时显示应评数、有效评分数、状态分布与评分覆盖率. 不将 null 当 0, 也不隐藏 null 造成的覆盖缺口. 如果某个高风险样本的证据缺失, 不能因为其他样本均分高就宣布准出.

## 6. 裁判也需要被校准

第 12-13 页要求人工和模型在相同输入及评分标准下独立评分. 不一致时先区分数据缺失、标准边界模糊或模型理解偏差, 而不是把人工答案透露给模型后重打分. 中间档占比过高时, 简单一致率容易显得很好; 原文提出看加权 Kappa、0 分问题样本召回率及人与人的一致性上限.

**教学展开:** 加权 Kappa 比较观测分歧和由边际分布产生的期望分歧. 线性或二次权重要事先固定. 若所有标注集中到同一档, 期望分歧为零, 该指标可能不可定义; 不应硬显示 1. 0 分召回率是“人工判为 0 的样本中模型也判为 0 的比例”, 没有人工 0 分样本则为 N/A. 两者还应结合混淆矩阵、分层样本量与人工标注质量看.

新评测版本的分数升高不等于裁判更准. 原文要求在同一批样本比较新旧结果, 由评审者判断是否更符合评分标准. 我们的演示采用固定人工标签和合成裁判标签, 只计算这些指标, 不伪造真实专家评审.

## 7. 可回放的条件, 不等于逐字复现

第 13-14 页同时固定输入快照与实际生效的评测配置. 回放先核对快照版本、用户、请求时间、内容集合及数据状态; 不一致时拒绝回放, 不偷偷拉取新数据补全旧样本. 使用旧配置追溯原条件, 显式替换某项配置才是在比较评测器.

![回放前校验与实验下钻](/images/redtech-evaluation/replay.svg)

模型随机性、推理参数及外部实现变化仍可能造成结果差异, 所以“可追溯”不等于每次生成逐字相同. 这是评测重放; Agent 的任务断点恢复另涉及外部副作用与对账, 两种回放不可混同.

第 15-18 页要求先看有效样本、分布、低分请求和单篇/列表差异, 再沿维度 → 请求 → 有序内容 → 单项结果 → 输入证据下钻. 两个相同均值也可能有不同低分群体. 语义结果能够定位“哪里表现不同”, 但不能单独证明问题根因来自召回或排序, 更不能替代真实行为效果与后续实验.

## 8. 连续用户模拟是探索方向

第 19-20 页将 LLM-as-User 与当前的语义判断分开: 连续模拟还涉及动作概率、消费后的兴趣与疲劳状态更新. 必须分别验证动作、群体行为分布和历史实验方向, 误差可能随多轮累积. 原文定位为上线前的预筛与探索, 不替代线上 A/B 实验. 我们没有实现真实用户模拟, 不在演示里展示伪造的预测点击率.

## 9. 融合进我们项目的具体位置

| 现有模块 | 本次补充 | 可观察证据 |
| --- | --- | --- |
| Harness 任务记录 | 一次任务快照及证据顺序 | snapshot_id、任务目标、环境与工具观测 |
| RAG 目标适配器 | 缺材料、取材料失败、只返回答案分开 | 能评哪些维度与各自分母 |
| 规则与模型评分器 | 证据白名单、明确粒度、独立状态 | score / reason / status / version |
| 版本评测 | 输入与评分配置双版本校验 | 拒绝混用新输入与旧分数 |
| 报告 | 分布、失败覆盖与逐条下钻 | 不只一个总分或一段结论 |
| 人工校准 | 一致率、加权 Kappa、低分召回 | 样本量、混淆矩阵和分歧原因 |

这是对已有设计的增补, 没有引入真实后端服务. 独立文章保留推荐系统原始边界, Wiki 评测章则链接本页并记录项目迁移契约.

## 10. 可操作练习与验收

浏览器打开实验室的“项目证据实验”, 无需账号和密钥. 先选择“小红书机制迁移”, 每次修改条件后重新逐步运行:

1. 使用完整上下文, 查看独立维度分数与理由. 验收: 0 分仍参与有效评分, 分母不只剩高分.
2. 切换材料缺失、获取失败、裁判失败和未请求目标维度. 验收: 各自状态与 null 分数独立显示, 不被均值吞掉.
3. 切换快照不一致. 验收: 停止回放, 不输出可比较的分数.
4. 修改合成行为数据. 验收: 语义评分输入不包含这些字段, 原分数不随行为字段改变; 行为仅在报告里并列.
5. 切换校准标签分布. 验收: 有效混淆矩阵实际计算, 无 0 分标签时低分召回 N/A; 单一类别导致期望分歧为 0 时 Kappa 为 N/A.

上述验收针对教学代码, 不是小红书或我们项目的线上质量证明. 检查范围见 [实验室检查记录](/demos/agent-lab/verification.json).

## 术语

| 名称 | 含义与本文用途 |
| --- | --- |
| EvaluationContext | 一次推荐的现场信息, 原文核心评测单元 |
| LLM-as-Judge | 模型依据限定证据和标准进行语义评分 |
| Rubric | 各档评分条件, 不让模型临时发明尺度 |
| Snapshot | 保存当时输入, 与评分配置一起追溯差异 |
| Weighted Kappa | 校准有序标签的一致性指标, 需要固定权重 |
| CTR | 点击率, 反映行为而非直接证明内容质量 |
| LLM-as-User | 模拟用户连续行为的探索方向, 不等同裁判 |
| Harness | 组织状态、工具和证据的运行控制层 |
