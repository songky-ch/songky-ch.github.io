## 开发专家视角

### 怎样让检索评分器算出的指标可比较?

**关注点**: 评价单元、K与去重、标注和版本.

**表达顺序**: 固定任务与证据 → 定义边界 → 计算 → 披露例外.

**我的回答**: 先固定问题、快照、账号范围和相关标注, 再明确按资料还是片段计数. 本例相关集合为 C101/C102, 原始前三项为 G201/C101/C103, 所以 Recall@3=1/2, Precision@3=1/3, 首个相关在第二位, RR@3=1/2. 我还要固定不足K是否按缺位计分、重复ID是否占位置、在哪层取结果. 本篇是先截原始前K, 重复项后续位置不贡献命中, 不向后补位. 不同约定可以存在, 但不能混着比较.

**进一步讨论**: 没有任何相关资料的题, Recall怎么处理?

分母为零, 不应临时填满分或偷偷排除. 本例单列无答案题, 测空证据处理. 还要区分无权限与检索错误, 它们不是知识库确实没有资料. 对未标资料先补标或记未知, 不默认为不相关.

**我需要避免的判断**: 只说用了某框架默认分数, 没讲它如何处理空标注、缺位与重复, 结果难以复核. 修改切分后不更新标注也会让比较失真.

## 测试专家视角

### MRR很高, 为什么仍可能无法完成问题?

**关注点**: 首个命中与完整证据、任务分层、宏微平均.

**表达顺序**: 给反例 → 增加覆盖检查 → 分组报告 → 限定结论.

**我的回答**: Q1 需要 C101 和 C102 两份证据, 但如果只把 C101 放第一, RR 已等于1, 仍漏掉 C102. 因此还要检查全部必需证据组是否覆盖. 合成百题报告中80条单证据题有72条找齐, 20条双证据题只有12条找齐、6条找到一份、2条没找到. 总体至少命中率90%, 完整覆盖84%, 而双证据组完整覆盖仅60%. 我会先暴露这个弱项, 不用总体命中率表示任务完成率.

**进一步讨论**: 这份报告宏平均召回87%, 微平均85%, 哪个算错了?

都可以成立. 宏平均逐题等权: (72+12+6×0.5)/100=87%. 微平均先汇总命中资料102份、应找120份, 得85%. 相关资料更多的问题在微平均里权重更大. 要提前约定主口径并保留分组, 不拿两种值当版本提升.

**我需要避免的判断**: 检索证据齐全也不证明回答忠实, 需要后续生成评测. 权限失败更不能被高召回或高nDCG抵消; 指标必须和业务门槛一起看.

## 术语与依据

| 英文名称与缩写 | 中文含义 | 本篇具体作用 |
| --- | --- | --- |
| Recall@K / Precision@K | 召回 / 精确率 | 分别衡量找全与返回有用程度 |
| RR / MRR | 倒数排名 / 平均值 | 只看首个相关结果 |
| nDCG / Evidence coverage | 排序增益 / 证据覆盖 | 区分排序质量与任务证据是否足够 |
| Macro / Micro | 宏 / 微平均 | 不同分母和权重 |
