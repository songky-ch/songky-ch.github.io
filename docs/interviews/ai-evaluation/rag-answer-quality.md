# R4 面试记录: 我怎样判断 RAG 回答是否可靠

<p class="article-kicker">面试记录 · R4 · 判断依据与经验边界</p>

对应[工作笔记](../../learning/ai-evaluation/rag-answer-quality.md). 我已有的基础是 Web 功能测试、Postman 排查和 SQL 数据核对. 下文整理我会怎样将这些判断方法迁移到 RAG 回答评测, 属于尚未落地的设计, 不作为已完成的项目经历. C101/C102、日期和评分均为 D3 合成场景.

## 开发专家视角

### 回答内容看起来正确, 为什么还要检查上下文和引用?

**关注点**: 参考事实与实际上下文的区别, 对象关联, 版本和引用支持.

**表达顺序**: 说明三份材料 → 给出不一致例子 → 分项留证据 → 确定排查方向.

**我的回答**: 我会同时保存独立参考、本次真正传给生成模型的上下文和最终回答. 事实正确性对照独立参考, 忠实性检查上下文是否支持断言. 如果参考是 v2, 上下文仍是 v1, 模型可能准确复述旧信息, 但不符合当前业务事实. 这时需要检查同步与版本选择, 不能仅凭最终错误认定模型编造.

引用还要单独检查. 假设 C101 和 C102 都属于 SITE-A, 回答说“C102 属于 SITE-A”, 却引用 C101. 这句话与参考一致, 引用 ID 也存在, 但 C101 没有证明 C102 的归属. 我会保存断言与具体引用片段的对应关系, 不用关键词命中代替支持关系.

**进一步讨论**: 引用指向同一份文档, 文档中明明有答案, 为什么仍不能直接通过?

我会核对本次片段和版本. 检索返回的片段可能没有支持该断言的句子, 甚至引用到更新后的内容, 无法复原模型当时的依据. 如果产品允许跳转整篇文档作为引用, 也需要约定可追溯的位置与版本. “引用能打开”只能验证可访问性, 不能证明生成过程有依据或关联的结论正确.

**我需要避免的判断**: 用独立参考替换模型实际看到的上下文来算忠实性; 或者只核对引用 ID 存在, 不核对对象、时间与事实关系. 这会掩盖检索遗漏、串记录和无依据回答.

## 测试专家视角

### 支持比例 75%、引用可解析率 100%, 为什么这条回答仍然失败?

**关注点**: 指标分母, 必答项与附加断言, 关键违规, 未决评分.

**表达顺序**: 固定任务 → 拆出断言 → 算清各分母 → 解释失败与未知.

**我的回答**: 我先看任务要求. 本例要 C102 的发生时间、局点、客户和问题现象. 候选答对时间、局点和客户, 却漏掉“复测告警”, 另写“根因已确认是连接器故障”. 上下文只支持前三条, 所以支持比例 3/4=75%; 必答项也只完成三项, 完成比例 3/4=75%. 两个比例数值相同, 评价对象不同.

候选有三个引用标记, 都能解析, 但一个把 C102 的局点指向 C101, 一个用“根因未确认”的记录支持“已确认故障”, 只有时间引用有效. 因此引用支持比例是 1/3, 四条需引用断言中的有效覆盖是 1/4. 我不会平均这些数值放行. 缺少必答现象与把未知根因写成已确认, 已经违反这条任务的约定.

**进一步讨论**: 模型评分器超时, 这次应该判失败还是不计入统计?

我会先保留已确认的证据. 如果规则或人工已经确认越权、缺字段等违规, 任务可以判失败, 同时记录模型评分未完成. 如果没有明确违规, 关键语义判断又未完成, 就记为待复核. 报告保留全部计划尝试及各状态, 不把超时静默删掉后汇报更高的通过率, 也不将评测基础设施异常当作业务回答已错.

**我需要避免的判断**: 无事实断言就把忠实性填满分; 无引用就自动认为不需要引用; 或把参考未覆盖的断言当成客观事实错误. 我会按任务类型约定空分母与合理说明的处理. 如果知识库有答案但上下文漏了, “当前证据不足”可以是合规的生成行为, 端到端任务仍未完成.

## 术语与依据

| 英文名称与缩写 | 中文含义 | 本文具体作用 |
| --- | --- | --- |
| RAG / Claim | 检索增强生成 / 事实断言 | 将回答拆成可关联到证据的对象与字段关系 |
| Factual correctness / Faithfulness | 事实正确性 / 忠实性 | 分别对照独立参考和实际上下文 |
| Completeness / Citation support | 完整性 / 引用支持 | 区分必答项完成与引用是否真正支持断言 |
| Grader / Unresolved | 评分器 / 未决项 | 保留判定证据, 不把评分异常当作通过 |

核查日期: 2026-10-23. 定义依据为 Ragas stable 文档的 [Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)与 [Factual Correctness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/factual_correctness/). 案例和引用口径为独立方案, 仅作手工推演; 未执行真实检索、Ragas 或公司 LLM API.
