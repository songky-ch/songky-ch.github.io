# 上下文驱动的评测 Agent: 开发与测试面试

[对应原文带读](../../learning/ai-evaluation/redtech-evaluation.md) · <a href="/demos/agent-lab/index.html" target="_self">动态练习</a> → 项目证据实验 → 小红书机制迁移.

依据 REDtech 原文机制与明确标识的测试项目迁移, 不是个人生产履历. 原文阅读范围和页码见带读文章; 以下回答组织及测试方法为教学补充.

## 开发视角

### 1. 为什么不用一个 Prompt 直接打总分?

**考察点:** 评测单元、职责与证据边界.

**回答顺序:** 被评对象 → 所需材料 → 分维度执行 → 结果契约.

**参考答案:** 推荐任务要还原用户当时的状态、请求时间和完整有序列表. 测试助手则固定需求版本、环境、计划和工具观测. 结构化事实由代码判断, 语义问题才交给限定证据的模型. 每个维度保存分数、理由与状态, 汇总之前先检查材料覆盖和关键风险, 不让流畅的总评盖住越权或缺证据.

**追问:** 某维度需要统计信息又需要语义理解怎么办? 先由代码确定计数和比例, 模型仅解释这些统计在当前场景下是否合理. 不让模型重算并覆盖确定性事实.

**判断依据:** 能说明输入字段、评分粒度和责任分工; 只说“优化 Prompt 提升准确率”不够.

### 2. 评分版本更新后平均分提高, 能发布吗?

**考察点:** 裁判校准与评测器漂移.

**回答顺序:** 冻结样本 → 独立标注 → 配对比较 → 风险准入.

**参考答案:** 不能直接发布. 提高可能只是新裁判更宽松. 让人工和模型在相同材料与标准下独立评分, 分歧定位到缺材料、标准不清或理解偏差. 看混淆矩阵、一致率、加权 Kappa、人工 0 分样本的召回, 并保留人与人的分歧. 新旧版本在同一批样本比较, 判断是否更符合标准, 不是谁打分高谁好.

**追问:** 全部样本都为 1 分且完全一致呢? 一致率为 1, 但加权 Kappa 的期望分歧为 0, 不能正常定义; 没有人工 0 分样本, 0 分召回也为 N/A. 需补齐具有代表性的低分边界样本, 不是硬补两个 100%.

**判断依据:** 解释指标分母与退化情况, 不把独立模型等同于可靠真值.

### 3. 评测回放与任务断点恢复有什么差别?

**考察点:** 输入版本、可追溯性与副作用.

**回答顺序:** 目的 → 校验对象 → 不一致出口 → 保证边界.

**参考答案:** 评测回放重用冻结材料与生效配置来追溯评分. 用户、时间、内容集合或状态不匹配就拒绝, 不拉新资料冒充旧现场. 明确改变配置后才做版本对照. 断点恢复是继续业务任务, 还要查询外部写入结果、校验当前授权并复用幂等键. 两者都不能承诺任意故障下逐字、逐步、100% 重现.

**追问:** 写接口成功后, 检查点落盘失败怎么办? 用持久操作键查询业务效果, 已提交则复用结果, 效果未知就对账或人工介入; 不从旧检查点推断“没执行”.

**判断依据:** 同时考虑外部业务账本和本地状态, 不以恢复聊天摘要代替恢复任务.

## 测试视角

### 4. 怎样发现“平均分好看但报告失真”?

**考察点:** 状态隔离、分母与风险分层.

**回答顺序:** 构造对照数据 → 计算预期 → 逐项比对 → 下钻证据.

**参考答案:** 同时放入有效 0 分、材料缺失、获取失败、裁判失败和未请求维度. 检查后三类失败不能变成 0, 未请求不计入应评分母, 有效低分不能被过滤. 报告展示应评数、实评数和分布; 关键样本缺证据应阻止准出. 再核对同样均值但不同低分分布的两组, 确认能下钻到请求、内容及原因.

**追问:** 裁判超时要重跑被测 Agent 吗? 通常应保留原观测仅重试评分, 否则被测产物变了, 无法归因. 是否重跑目标须另立实验并记录版本.

**判断依据:** 给出可复算预期而不是只截图一个总分.

### 5. 如何验证行为数据没有泄漏给语义裁判?

**考察点:** 输入白名单与可解释对照.

**参考答案:** 保持语义快照与裁判配置不变, 只改变曝光后的点击或测试产物采纳记录. 检查发给裁判的实际载荷, 确保不含这些字段; 本页确定性样例的评分应完全相同. 真实随机模型不能仅以输出不同判泄漏, 应先审计输入、调用参数和种子. 行为效果在后续报告中另行关联.

**追问:** 参考答案也不能给裁判吗? 不是. 参考答案是否允许由评分契约决定. 要区分任务允许的参考证据与本应隐藏的验收标签、版本名或后验行为信息.

**判断依据:** 能指出具体载荷检查, 不仅凭回答猜是否泄漏.

### 6. 离线语义评分更好能证明线上提升吗?

**考察点:** 相关、因果与用户模拟边界.

**参考答案:** 不能. 先看样本可比性、有效覆盖和分层分布, 定位内容差异; 再结合召回、排序等实际日志提出可检验假设, 用真实业务实验验证. LLM-as-User 的连续模拟还涉及状态更新和误差累积, 需验证动作、群体分布和实验方向; 可以预筛, 不能替代真实 A/B.

**追问:** 测试助手该怎么落地? 内容覆盖率与越权率独立评测, 节省工时和缺陷发现效果用真实任务记录比较, 不用合成页面算出一个假的收益百分比.

**判断依据:** 能说明需要什么额外证据才能得出业务结论.

## 练习与验收

在动态实验中运行 8 个“小红书机制迁移”情境. 完整证据时应得到三档分布 [1,1,1]; 缺材料时应评 3、有效评分 2; 未请求目标时应评 2、有效评分 2; 快照不匹配停止回放. 固定四条校准标签的一致率为 0.75、线性加权 Kappa 为 5/7、0 分召回为 0.5. 这些是合成样例计算值, 不是原文效果数据.

## 术语速查

| 术语 | 本文作用 |
| --- | --- |
| LLM-as-Judge | 基于限定证据的语义评分 |
| Rubric | 独立于单次模型输出的分档标准 |
| Weighted Kappa | 扣除边际分布影响后的有序标签一致性 |
| Snapshot | 固定原始现场, 不混用新旧材料 |
| Idempotency | 同一操作重试不重复产生业务效果的服务契约 |
| LLM-as-User | 连续行为模拟, 需要额外校准 |
