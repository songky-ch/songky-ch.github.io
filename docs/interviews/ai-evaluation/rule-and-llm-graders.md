## 开发专家视角

### 为什么不能让一个大模型直接给 Agent 打总分?

**考察点**: 结构化事实、语义标准、汇总优先级.

**回答结构**: 拆维度 → 按证据分工 → 汇总 → 处理裁判异常.

**参考答案**: 结构化字段适合确定性规则, 比如工具名称、归一化日期、派发次数和业务写入. 自由文本是否忠实、完整, 可以让模型按明确标准判断, 但需要独立证据和简短可核对的理由. 我不会让表达流畅的高分抵消越权写入. 汇总先看是否已有可靠失败, 有则失败; 没有失败但必需项未知则未知; 必需项全通过才通过. 不适用项单独记, 不等同于失败.

**递进追问**: 裁判输出格式正确且证据编号存在, 就可信了吗?

还不够. JSON 合法只证明能读取, 编号存在只证明材料存在. 要抽查材料是否实际支持理由, 对照待评答案检查遗漏和新增主张. 模型超时或非法输出属于裁判异常, 不能直接当 Agent 失败.

**易错回答与判断依据**: 只给一个没有维度定义的 90 分, 无法知道是否符合任务. 用候选回答本身当标准答案也会形成自证循环.

## 测试专家视角

### 裁判与人工一致率 86%, 可以直接上线吗?

**考察点**: 误放风险、混淆矩阵、独立校准.

**回答结构**: 还原计数 → 看错误方向 → 按风险判断 → 查样本来源.

**参考答案**: 不能只看一个比例. 教学快照中人工通过 50 条, 裁判接受 42 条、拒绝 8 条; 人工失败 50 条, 裁判接受 6 条、拒绝 44 条. 总一致率是 86%, 但坏答案误放率为 6/50=12%, 通过判定的可靠比例为 42/48=87.5%. 这是否可接受取决于风险, 没有通用及格线. 调试裁判的 40 条开发答案与这 100 条验证答案必须分开, 人工分歧也要回到契约复核.

**递进追问**: 换一个更强模型, 是否可以省掉校准?

不能. 裁判可能偏爱冗长表达、受候选文本中的指令影响, 或漏看客户范围. 应固定同一证据和答案重复判分, 比较简短与冗长等语义等价样本, 并保留模型和标准版本. 多个裁判同意也不等于独立证据充分.

**易错回答与判断依据**: 把模型自报的 0.98 信心当 98% 准确率, 或引用论文中其他场景的一致率为本系统担保, 都缺少本场景证据.
