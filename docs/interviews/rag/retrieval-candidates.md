## 开发专家视角

### 关键词检索、向量检索、过滤和重排各做什么?

**关注点**: 精确约束与相似性、候选边界、分数语义.

**表达顺序**: 明确范围 → 两路找候选 → 融合 → 重排与上下文.

**我的回答**: 过滤先限定允许搜索的范围, 比如账号可访问的客户和发生日期. 关键词检索利用原词、编号等匹配, 向量检索补充近义表达, 两者都不能代替权限. 合并时不能直接把 BM25 分数和向量相似度相加, 可以用各路名次贡献融合. 重排再比较问题与已有候选, 但 C102 没进入任何候选, 普通重排无法凭空把它找回来. 最后还需检查上下文实际保留了哪些片段.

**进一步讨论**: RRF 的常数 60 是返回60条吗?

不是. 本例每路贡献 1/(60+名次), 60 控制名次差距的权重, 与候选数 K 分开. C102 两路都第一时是 2/61, 若两份资料分占两路第一第二则可能同分. RRF 分数不是相关概率, 平分处理也要明确.

**我需要避免的判断**: 把混合检索当必然优于单路、把重排当补全全库、把分数当概率, 都缺少适用前提和实测依据.

## 测试专家视角

### 怎么证明空结果是后过滤造成的, 而不是库里没有?

**关注点**: 集合变化、过滤位置、受控对比.

**表达顺序**: 固定快照 → 核对索引 → 保存各层候选 → 只变过滤位置.

**我的回答**: 我先在固定快照确认 C102 确实存在且符合账号和日期范围. 示例未过滤排序前四是 C105、C103、C102、C101, 若先截前二再过滤, 前两项都被排除, 结果就空了. 保存截断前后与过滤后的 ID, 可解释记录怎样消失. 再在合法范围 C101/C102 中检索作受控对比, 检查目标是否回来, 同时记录时延与候选数. 这验证的是该配置与样本, 不能推导所有前过滤都无损.

**进一步讨论**: 切分策略变了, 老 benchmark 还能直接跑吗?

任务文字可以保留, 但片段 ID 和跨度可能改变. 应通过稳定资料 ID、版本与必要事实重新映射和复核标注. 两个重叠片段来自同一问题, 不能因此算两条问题命中. 评价单元要在比较前固定.

**我需要避免的判断**: 一次同时换切分、模型、过滤和K, 即使分数提高也很难归因. 未授权资料即便只发给重排模型, 也超出了本例允许范围, 不能只在最终页面隐藏.
