# 业务级 Agent 生产落地面试: 开发与测试双视角

[先读机制与分支](../../learning/agent/production-agent.md) · <a href="/demos/agent-lab/index.html" target="_self">打开动态演示</a>, 选择“生产决策与面试”. 本文为技术参考答案, 不代表你已做过生产项目. 不编造上线指标, 不保证这些问题一定出现在面试中.

## 开发专家视角

### 01 项目背景与选型

**面试问题:** 专项测试助手解决什么问题, 为什么需要 Agent?

**考察点:** 业务价值、确定性边界、对照实验

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 从测试人员整理需求、选择接口和汇总证据的耗时讲起. 固定测试套直接交给工作流; 需求缺信息、需要根据反馈选择下一步时才引入模型决策. 创建任务、权限校验和执行测试仍由程序完成. 上线前后在同类任务中比较全量合格率、人工处理时间、P95 延迟和每个合格任务的总成本, 同时保留人工或工作流基线. 没有真实数据就说明尚未上线, 不编造提升比例. 重做时优先补齐基线、证据日志和高风险操作边界.

**递进追问与答案:** 如果 Agent 更慢但节省人工呢? 分开统计机器等待和人工处理时间, 结合业务时限与风险评估净收益, 不能只比较响应速度.

**易错回答与判断依据:** “因为业务复杂所以用 Agent”缺少动态决策的具体需求和基线.

### 02 任务执行与重规划

**面试问题:** 模型和代码各决定什么, 如何限制连续工具调用?

**考察点:** 依赖顺序、动态计划、无进展检测

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 模型提出下一步工具与参数, 运行时维护状态并检查身份、参数、预算和审批. 工具结果绑定 call_id 返回, 模型再决定下一步. 有数据依赖的调用串行; 无依赖且资源允许的只读调用可以并行, 写操作不能默认并行. 新证据推翻计划时保留已完成事实, 更新剩余计划版本; 如果审批覆盖的目标或参数改变, 原审批失效. 用硬上限和无进展检测共同终止循环, 不能只在提示词里说不要循环.

**递进追问与答案:** 合法轮询也会重复调用, 怎么办? 轮询有独立次数、退避和期限; 无进展指状态与证据没有变化, 不能单凭相同工具名拦截.

**易错回答与判断依据:** “模型自己会停止”没有可执行的预算和终态.

### 03 工具错误与重试

**面试问题:** 参数格式正确但业务含义错, 或写操作超时, 怎么处理?

**考察点:** 工具注册、授权、语义校验、幂等

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 运行时只接受注册且当前身份可用的工具. JSON Schema 通过不代表业务正确, 还要核对租户、环境、资源归属、金额单位和前置状态. 选错工具或参数错误应返回结构化错误供有限次修正, 缺业务信息则询问用户. 权限错误不能靠换工具绕过. 暂时性读错误可在期限内退避重试; 写超时可能已经提交, 先查状态. 只有服务端支持稳定幂等键、参数一致性和去重保存契约时才能安全重放相同操作, 本地加个 UUID 并不够.

**递进追问与答案:** 服务端不支持幂等又无法查状态? 标记 UNKNOWN, 停止自动重试并交人工对账. 不能把超时解释为失败未执行.

**易错回答与判断依据:** “所有 5xx 都重试”忽略服务端已提交但响应丢失的情况.

### 04 框架选择与边界

**面试问题:** 框架帮忙做什么, 哪些责任不能交给框架?

**考察点:** 需求驱动选型、持久化、恢复语义

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 先列是否需要长任务、暂停恢复、流式事件、分支编排和可观测性, 再用故障样例验证框架. 简单单次调用可以用 SDK 加显式循环; 需要图状态和中断恢复时可评估 LangGraph. 它提供检查点及暂停恢复机制, 但业务权限、审批绑定、幂等契约、执行沙箱、队列容量和验收标准仍由应用落实. 不符合业务时优先通过节点与工具适配层扩展, 把业务状态与框架类型隔开, 而非直接修改框架内部.

**递进追问与答案:** 恢复是否从中断的那一行继续? LangGraph 中断所在节点恢复时会从节点开头重新执行, 中断前的副作用必须避免重复; 具体行为还要按锁定版本测试.

**易错回答与判断依据:** “框架有持久化, 就保证业务 exactly-once”混淆状态恢复与外部写入.

### 05 知识库与上下文

**面试问题:** 召回正确为什么还答错, 上下文超长怎么处理?

**考察点:** 检索与生成分层诊断、信息保真、权威数据

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 先确认正确片段真的进入本轮模型输入, 而非只存在于检索日志; 再检查切分是否缺条件、版本是否冲突、否定语义和引用是否错配. 冻结输入单独比较生成与提示词, 不把所有问题都归因于召回. 上下文预算给系统规则、任务状态、最新证据和输出留空间; 旧对话可以提炼摘要, 但审批、目标、未完成动作、来源版本等保存为结构化事实. 结构化检索用于精确过滤实体、权限和时间, 摘要用于压缩叙述, 二者互补. 库存、当前执行状态等事实应查权威业务接口.

**递进追问与答案:** 摘要删掉“禁止生产环境”怎么办? 约束不只保存在摘要, 执行前由程序读取不可被摘要替代的结构化限制, 回归检查关键事实保留率.

**易错回答与判断依据:** “扩大上下文窗口或统一总结就行”没有处理冲突、丢约束和实时性.

### 06 多轮对话与记忆

**面试问题:** 长期记什么, Redis 和向量库分别承担什么?

**考察点:** 短期状态、长期事实、隔离与过期

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 最近交互、待补参数和执行状态属于会话状态, 需要恢复的部分存持久化检查点; Redis 适合带 TTL 的缓存或协调状态, 不能默认是唯一事实来源. 稳定偏好与经确认的事实可以进入长期结构化存储, 带用户、项目、来源、有效期与版本; 需要语义回忆的叙述可建立向量索引, 权威事实仍可回查. 模型提炼的是候选记忆, 先筛敏感信息、冲突与时效再写入. 检索前强制身份和项目过滤, 命中后再检查权限; 删除与失效也要同步索引和缓存.

**递进追问与答案:** 用户更正记忆后旧向量仍召回怎么办? 用当前事实版本和墓碑标记拦截旧记录, 异步清理向量与缓存; 不把向量匹配结果直接当真.

**易错回答与判断依据:** “每个用户一个聊天 ID 就不会串数据”缺少存储和检索层的权限约束.

### 07 多 Agent 协作

**面试问题:** 为什么拆 Agent, 如何防重复、传结果和控成本?

**考察点:** 可并行子任务、任务契约、汇聚与写入归属

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 先验证单 Agent 或普通并行工作流是否足够. 只有独立子问题、不同上下文或工具边界等确实带来收益时再拆. 例如接口风险与 UI 风险分析可以并行, 若只是固定程序步骤就不需要两个 Agent. 委派包包含 task_id、父任务、目标、约束、输入引用、输出 schema、预算与截止时间, 回传证据和未决事项, 不复制全部聊天. 用任务账本、租约和去重控制领取; 旧执行者失去租约后须由版本栅栏阻止提交. 外部写入交给明确的单一责任者并使用幂等契约. 汇聚器处理矛盾与部分失败.

**递进追问与答案:** 并行是否一定更快? 总延迟含分派、最慢子任务和汇聚, 总成本含所有子任务及重试. 在同一任务集对比合格率、P95、总 token 和单个合格任务成本后再决定.

**易错回答与判断依据:** “多模型互相投票必然更正确”忽略相关错误、无证据共识与协调开销.

### 08 可信结果与运行治理

**面试问题:** 前一步成功后一步失败, 怎么恢复和定位成本延迟?

**考察点:** 环境证据、恢复、预算、分段追踪

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 把模型声称、工具传输成功、业务断言通过分开记录. 用任务 ID 串起模型调用、工具参数版本、授权、业务回执和断言. 恢复前先核对已完成的外部效果, 只恢复未完成部分; 补偿是新的业务动作, 也可能失败, 不能等同数据库回滚. 运行时在派发前限制总期限、模型调用次数、并发和费用预算, 在途操作超时仍需取消或对账. 延迟突增按排队、模型首字和总耗时、工具、检索及重试拆分, 再看 P95 与版本变化. 成本按输入输出 token、重复尝试、工具费用和成功任务数拆分.

**递进追问与答案:** 已经创建任务但报告生成失败? 对账确认任务存在, 使用原结果重做报告, 不重新创建任务; 若需要撤销则按业务补偿规则批准并执行.

**易错回答与判断依据:** “HTTP 200 就算成功”没有业务状态和验收断言.

### 09 版本评测与回滚

**面试问题:** 怎样比较模型、Prompt 和工具描述, 上线退化怎么回滚?

**考察点:** 冻结版本、分层样本、配对比较、灰度

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 把模型、提示词、工具 schema、检索索引和评分规则作为可追踪版本组合. 用来源合规的脱敏样本、真实失败类型和合成边界构建评测集, 留出未用于调参的测试集. 比较时固定环境和任务, 先单因素替换以定位原因, 最终再验证完整组合; 随机输出要重复采样, 报告样本数与不确定性. 规则检查权限与业务结果, 独立裁判评开放语义并用人工标注校准, 换个模型不能自动保证客观. 灰度监控合格率、违规、成本与延迟, 超阈值切回已验证版本; 在途任务按其原版本完成或受控迁移.

**递进追问与答案:** 回滚 Prompt 会撤销已经写入的订单吗? 不会. 行为版本回滚与业务补偿是两个过程, 后者需对账、权限和独立记录.

**易错回答与判断依据:** “回答看着更好就发布”缺少固定样本、明确分母和回滚条件.

### 10 落地限制与退出条件

**面试问题:** 哪些靠工程解决, 何时放弃 Agent?

**考察点:** 模型能力上限、必要自研、投入边界

**回答结构:** 先说场景和目标, 再说明模型与程序的职责、故障出口, 最后给出可核验的证据与取舍.

**参考答案:** 工程可以约束授权、预算、并发、重试和证据留存, 但不能保证模型在任意新需求上都理解正确. 自研重点通常是业务工具契约、权限策略、验收数据、环境断言和恢复规则, 不是必须重写通用调度或训练基础模型. 如果任务长期路径稳定、错误成本过高而又无法验证或审批, 应让确定性服务执行, 模型只做辅助解释或完全退出. 用满足业务风险约束后的净收益决定继续投入, 而不是因为已经用了某个框架就坚持.

**递进追问与答案:** 模型能力提升能取消所有工程约束吗? 不能. 身份、授权、幂等与审计是系统责任, 与模型是否聪明无关.

**易错回答与判断依据:** “所有问题多加提示词就能解决”没有识别不可验证目标和外部系统限制.

## 测试专家视角

### 01 项目背景与选型如何验收?

**面试问题:** 针对本主题, 怎样证明机制真的有效而不是只写在 Prompt 中?

**考察点:** 输入与故障覆盖、独立证据、预期终态、失败归因.

**回答结构:** 冻结前置条件 → 注入具体变化 → 观察执行与环境 → 判定结果和未覆盖范围.

**参考答案:** 选固定测试套与开放式需求两类样本, 固定验收口径, 同时记录失败、转人工、耗时与成本; 不只展示成功样例.

**递进追问:** 上线后平均耗时下降, 能证明 Agent 有效吗?

**回答要点:** 不能. 检查任务难度和流量组成是否改变, 按相同分层比较人工时间、全量合格率与尾部延迟, 同时纳入转人工成本.

**易错回答与判断依据:** 只展示页面上的成功提示, 没有对应输入、断言和环境证据, 不能证明上面的生产机制已实现. 本演示展示预设路径, 不作为这些生产测试已经通过的证据.

### 02 任务执行与重规划如何验收?

**面试问题:** 针对本主题, 怎样证明机制真的有效而不是只写在 Prompt 中?

**考察点:** 输入与故障覆盖、独立证据、预期终态、失败归因.

**回答结构:** 冻结前置条件 → 注入具体变化 → 观察执行与环境 → 判定结果和未覆盖范围.

**参考答案:** 注入相同结果反复返回、依赖缺失、计划变更和取消, 检查无进展终止、未授权调用次数为零及已完成步骤不被重复执行.

**递进追问:** 如何验证总预算不会被并行调用绕过?

**回答要点:** 设置只剩一次模型额度再同时请求两次调用, 应原子预留额度且只批准一次; 记录被拒绝派发, 对在途调用仍有期限和结果处理.

**易错回答与判断依据:** 只展示页面上的成功提示, 没有对应输入、断言和环境证据, 不能证明上面的生产机制已实现. 本演示展示预设路径, 不作为这些生产测试已经通过的证据.

### 03 工具错误与重试如何验收?

**面试问题:** 针对本主题, 怎样证明机制真的有效而不是只写在 Prompt 中?

**考察点:** 输入与故障覆盖、独立证据、预期终态、失败归因.

**回答结构:** 冻结前置条件 → 注入具体变化 → 观察执行与环境 → 判定结果和未覆盖范围.

**参考答案:** 模拟未知工具、跨用户资源、数量单位错、429、提交后断网, 核对调用被阻断或正确退避; 检查业务记录数量而非只看返回码.

**递进追问:** 如何测试幂等键复用但参数变化?

**回答要点:** 同一键第一次创建 test 任务, 第二次改成 prod 或改负载. 预期明确冲突而非创建第二笔记录, 同键同参数返回原结果; 核对业务表或受控服务记录.

**易错回答与判断依据:** 只展示页面上的成功提示, 没有对应输入、断言和环境证据, 不能证明上面的生产机制已实现. 本演示展示预设路径, 不作为这些生产测试已经通过的证据.

### 04 框架选择与边界如何验收?

**面试问题:** 针对本主题, 怎样证明机制真的有效而不是只写在 Prompt 中?

**考察点:** 输入与故障覆盖、独立证据、预期终态、失败归因.

**回答结构:** 冻结前置条件 → 注入具体变化 → 观察执行与环境 → 判定结果和未覆盖范围.

**参考答案:** 用最小流程验证进程崩溃、审批暂停与恢复, 检查节点重入、检查点可读性、旧版本兼容和外部写入次数; 不只跑官方 happy path.

**递进追问:** 如何验证框架恢复时不会重复写入?

**回答要点:** 在写入成功后、检查点保存前强制停止测试进程, 恢复后核对业务记录数量和操作 ID; 这个窗口比仅在节点之间正常重启更能暴露问题.

**易错回答与判断依据:** 只展示页面上的成功提示, 没有对应输入、断言和环境证据, 不能证明上面的生产机制已实现. 本演示展示预设路径, 不作为这些生产测试已经通过的证据.

## 新增工程题: 参考答案与验证追问

以下是教学参考, 不是“所有企业的标准答案”. [对应机制与来源](../../learning/agent/production-agent.md) · <a href="/demos/agent-lab/index.html" target="_self">项目证据实验</a>.

### 如何保证 Query 改写不改变意图?

**考察点:** 问题改写: 高相似也可能改错.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** 改写候选不能取代原问题. 检查实体、否定、数值单位、时间范围、权限和意图; 相似度只作辅助信号. 错别字纠正可能改变字面关键词, 所以保护的是规范化实体与约束, 不是所有原始字符.

**测试追问与参考答案:** 如何证明以上做法有效? 构造只改变否定、单位和实体的最小对照样本. 记录原问题、候选、保护槽位和决策; 同时评价召回收益与意图损坏率.

**进一步追问:** 遇到“指代不清, 先问用户”会怎样? 在实验中切换此情境, 先预测记录再逐步比对. 判断依据是解释输入、下一动作及不能保证的部分, 不是背框架名.

### 复杂 PDF 表格与 chunk 怎样处理?

**考察点:** 文档入库: 复杂表格与切片.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** 可用文本层优先解析, 扫描页按需 OCR. 表格保留行列、合并单元格、表头、单位与页码, 也可生成带表头的行组片段参与检索. 语义切片、固定长度和重叠都是可比较策略, 没有固定 512 必错的规则.

**测试追问与参考答案:** 如何证明以上做法有效? 检查双栏阅读序、跨页表头、单位、公式符号和出处. OCR 置信度不等于业务正确; 与抽样人工真值核对, 不明内容隔离复核.

**进一步追问:** 遇到“固定切片丢失否定条件”会怎样? 在实验中切换此情境, 先预测记录再逐步比对. 判断依据是解释输入、下一动作及不能保证的部分, 不是背框架名.

### RAG 的问题怎么定位而不是堆组件?

**考察点:** RAG 诊断: 不堆组件找证据.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** 先冻结失败现场, 分别定位解析、切片、召回、重排与生成. 重叠可能增加重复, 多路召回可能增加噪声, 重排可能增加延时; 用同一评测集比较改动, 不把整套组件当作必胜答案.

### Manager 如何防止重复任务与错误仲裁?

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

### Checkpoint 能否保证 100% 恢复?

**考察点:** 断点恢复: 写入与检查点之间.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** 检查点保存状态和结果引用, 不能原子覆盖任意外部服务. 恢复先加载持久化状态与实际操作账本, 再查询业务效果. 相同操作复用幂等键, 改参数必须新建操作并重新批准. 不承诺任意故障下 100% 恢复.

**测试追问与参考答案:** 如何证明以上做法有效? 在发送前、服务提交后、回执后、检查点落盘前分别注入故障. 断言业务记录数量、批准版本和下一动作, 不只看对话恢复了.

**进一步追问:** 遇到“副作用前崩溃, 服务支持幂等”会怎样? 在实验中切换此情境, 先预测记录再逐步比对. 判断依据是解释输入、下一动作及不能保证的部分, 不是背框架名.

### 调用模型 API 算部署模型吗?

**考察点:** 模型服务: 质量与资源准入.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** 调用托管 API 不等于部署模型. 自部署还需权重与许可证、运行时兼容、显存及 KV cache 容量、量化回归、并发调度与压测. 小模型/大模型路由要在业务集上验证; 灰度监控质量、延时和资源, 不只看 token.

**测试追问与参考答案:** 如何证明以上做法有效? 记录硬件、模型和量化版本、上下文长度分布、并发、首 token 延时与吞吐. 服务超时是否可以重试取决于流式输出和后续工具效果, 不能重复发送业务动作.

**进一步追问:** 遇到“服务超时但已开始输出”会怎样? 在实验中切换此情境, 先预测记录再逐步比对. 判断依据是解释输入、下一动作及不能保证的部分, 不是背框架名.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** 规则、分类模型和 LLM 是可选组合, 不必每次逐层经过. 多意图可形成任务依赖图, 不等于必须拆成多轮对话. 兜底占比须定义分母和路由触发条件; 没有证据支持成熟项目统一低于 5%-10%.

### MySQL 与 Redis 如何保持一致?

**考察点:** 记忆一致性: 持久记录与缓存.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** MySQL 可存消息、任务、事实与快照元数据, 大文档原件通常放对象存储并保存引用; Redis 可缓存会话且自身也可配置持久化. 关键消息和状态逐次落盘, 数据库事务同时写 outbox, 消费者按版本更新缓存; 不是等会话结束再保证一致性.

**测试追问与参考答案:** 如何证明以上做法有效? 测试缓存更新失败、乱序、重复事件、进程崩溃、删除后旧值复活. 重要决策读当前权威版本, 明确最终一致窗口和用户读己之写要求.

**进一步追问:** 遇到“等会话结束才落盘的风险”会怎样? 在实验中切换此情境, 先预测记录再逐步比对. 判断依据是解释输入、下一动作及不能保证的部分, 不是背框架名.

### RAG 准确率应该如何定义?

**考察点:** RAG 指标: 名称不能代替定义.

**回答顺序:** 定义边界 → 说明机制 → 给出失败出口 → 用可观察证据验证.

**开发参考答案:** 区分召回、证据支持、事实正确、问题相关性与运营可靠性. 忠实不必然正确, 幻觉率也只有在相同断言集合和二分类规则下才是 1-忠实度. 线上脱敏抽样、人工复核、漂移告警与冻结回归集互补, 不能只监控一个准确率.

**测试追问与参考答案:** 如何证明以上做法有效? 固定相关性标注粒度和分母, 分别统计不适用、失败和有效评分. 问答匹配可定义为回答覆盖任务要点, 不等于语义相似度; 上下文相关性需相关性标签或独立裁判.

**进一步追问:** 遇到“没有可核验断言”会怎样? 在实验中切换此情境, 先预测记录再逐步比对. 判断依据是解释输入、下一动作及不能保证的部分, 不是背框架名.

### 如何介绍一个完整 Agent 项目?

**考察点:** 业务问题、个人贡献、工程取舍和真实证据.

**参考结构:** 场景与基线 → 你的实际工作 → 一次典型失败 → 处理机制 → 实测证据 → 未完成边界. 当前可如实说“我设计了专项测试助手的架构学习案例, 用浏览器模拟验证审批、版本与评分分支”; 不能说已上线或已部署模型. 原有“项目背景与选型”主题提供业务取舍分支.

**追问与答案:** 没有线上指标怎么办? 明确没有, 展示可复算的模拟记录和测试覆盖, 再说明真实评估需要同类任务基线及采样方案. 不把测试通过率冒充业务成功率.

**测试判断依据:** 能复现特定失败并解释断言, 不把模拟与生产结果混在一起.

新增术语: outbox 是事务中写入的待投递事件记录; tombstone 是防止旧事件恢复已删除数据的墓碑记录; lease version 是拒绝迟到执行者提交的所有权版本; KV cache 是推理时缓存注意力键值的内存, 会影响容量. 对应来源见配套机制文章的“资料与保证边界”.
