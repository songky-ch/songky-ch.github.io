# 01. 目标、约束与决策

[返回目录](./index.md)

## 1. 已确认的范围

| ID | 要求 | 设计落点 |
| --- | --- | --- |
| R01 | 企业内部使用, 每人唯一工号, 登录用户均能使用模型 | 用户级身份与数据隔离, 暂不建设分级角色体系 |
| R02 | Windows 客户端, 希望包含 WebView2 | 桌面壳 + 工作台 + 独立内网浏览区域 |
| R03 | Linux 后端, 不使用 Docker | 一个常驻业务主服务, 允许启动并回收任务子进程 |
| R04 | 测试不在用户电脑运行 | 所有接口、UI、负载测试和解析任务在服务器运行 |
| R05 | 通用对话、意图、参数、工具、多轮、工作流 | Agent 运行层与工具注册表 |
| R06 | 短期与自动总结的长期记忆 | 持久记录 + 会话缓存 + 语义索引 |
| R07 | Agentic RAG, 内部与外部知识库评测 | 可限步的检索流程 + 独立评测模块 |
| R08 | 执行过程中合适地人工介入 | 持久化输入请求、审批请求和恢复点 |
| R09 | 含图片和流程图的需求生成用例, 复用 Skill | 文档解析、流程结构、来源定位、Skill 加载 |
| R10 | 接口套件、UI 脚本、压力与性能测试 | 独立适配器, 共用任务和报告机制 |
| R11 | 流式反馈、异步长任务、多任务 | 事件流与执行生命周期分离 |
| R12 | 暂不做完整测试管理闭环 | 每次专项任务保留配置、执行证据、报告即可 |
| R13 | Wiki 与核心注释是重要交付物 | 每个模块附调用链、状态边界、验证证据 |
| R14 | 先评审方案再开发 | 当前只新增 Wiki 与图解, 不编写业务实现 |

## 2. 建议决策记录

| ID | 决策提案 | 原因 | 状态 |
| --- | --- | --- | --- |
| D01 | 模块化单体, 一个 API/Agent/调度主进程 | 符合单人建设和单服务部署要求 | 待评审 |
| D02 | WPF + WebView2 桌面壳, React + TypeScript 工作台 | 保持 Windows 集成与复杂交互的分工 | 待评审 |
| D03 | Python + FastAPI + Pydantic + LangGraph | 工具生态、显式状态图、参数与接口契约 | 待评审 |
| D04 | PostgreSQL 同时承载业务记录、任务队列和检查点 | 减少队列与数据库之间的双写一致性问题 | 待评审 |
| D05 | pgvector 作首期语义索引, Redis 作缓存与限流 | 不单独引入向量数据库和分布式任务框架 | 待评审 |
| D06 | 原始文档、图片、脚本和报告先使用服务器文件存储 | 单机部署简单, 元数据仍存数据库 | 待评审 |
| D07 | pytest/HTTPX 接口测试, Playwright Python UI, k6 负载测试 | 以成熟工具执行, 模型不负责虚构判定 | 待评审 |
| D08 | OCR/版面解析采用 PaddleOCR 候选, 多模态模型理解流程 | OCR 和流程关系理解分别承担职责 | 待样本验证 |
| D09 | Skill 按 Agent Skills 目录格式导入, 权限在平台侧管理 | 复用方法与资源, 不把文字当授权机制 | 待实际样例 |
| D10 | 固定评测集 + 规则计算 + 独立裁判 + 人工校准 | 减少自评偏差, 支持复现与版本比较 | 待评审 |
| D11 | 一个进程内调度循环, PostgreSQL 租约与唯一调用记录 | 首期不引入 Celery/Temporal/Kubernetes | 待故障验证 |
| D12 | 任务 runner 在无 Docker 的 OS 隔离环境执行 | 保留 Linux 资源与访问边界 | 阻塞生成脚本执行, 待运维验证 |

这些组件形成一个建议方案, 不要求立刻采购、安装或绑定厂商. 暂不建设可视化任意工作流设计器、插件市场、多 Agent 群体或分布式压测集群.

## 3. 未解决的问题及影响

| ID | 最小缺失信息 | 影响 | 验证方式 |
| --- | --- | --- | --- |
| Q01 | 公司批准的身份验证入口, IDaaS 协议及会话规则 | 无法可靠上线登录 | 与身份系统负责人确认验证接口/网关与获准方式, 不要求提供密码 |
| Q02 | 业务会话是否绑定设备、IP、应用或证书 | Linux 是否能代用户调用 | 使用授权测试身份验证最小只读调用, 检查过期与撤销 |
| Q03 | Linux 发行版、systemd/cgroup 能力及运维权限 | 子进程隔离与浏览器依赖 | 建立 OS 能力检查记录 |
| Q04 | 模型网关协议、能力、数据处理范围和配额 | 工具调用、视觉、检索和评测 | 能力探测矩阵与脱敏样本, 不先指定模型商品名 |
| Q05 | 并发用户、任务数、文档大小、预期负载 | 容量和超时上限 | 使用实际目标制定容量表, 本稿不冒称支持量 |
| Q06 | 现有数据库、Redis、监控与证书设施 | 部署组件数量 | 盘点可复用基础设施 |
| Q07 | 已有 Skill 样例及许可/运行依赖 | 精确兼容范围 | 导入一个脱敏样例, 校验路径和工具映射 |
| Q08 | 外部知识库输出字段, 是否有检索片段和标注 | 能测哪些指标 | 填写评测适配器能力表 |
| Q09 | 脱敏需求文档, 含复杂流程、表格与图片 | OCR/视觉质量与算力选型 | 建立样本与人工标注 |
| Q10 | 数据保留、删除、备份恢复目标 | 存储与运维策略 | 评审保留期、RPO/RTO 和备份覆盖 |

Q01 不可通过“客户端上传工号”替代. Q02 不可通过“导出了 Cookie”宣布通过. Q03 不通过时, 不开放任意生成脚本执行; 这属于能力未就绪, 不是偷偷换到用户电脑执行.

## 4. 不混淆三种状态

- 设计已写: 本 Wiki 描述了预期行为.
- 方案已确认: 用户接受选型与边界, 待解决问题有明确处理方案.
- 工程已验证: 在目标环境运行并保存证据, 结果符合验收标准.

本次仅达到第一种. 文档中的示例数据、延时、负载均不代表公司环境实测值.
