## 8. 开发前的四个验证门

### Gate A: 认证可行

输入: 身份系统说明、允许的验证接口和授权测试用户. 步骤: Windows 登录 → 服务端验证身份 → Linux 只读访问目标 → 过期/退出检查. 证据: 脱敏状态与绑定关系. 未通过则身份相关实现方案不冻结.

### Gate B: 执行边界可行

输入: 目标 Linux OS、运维允许配置和受控测试脚本. 步骤: 启动任务 → 验证文件/网络边界 → 超时/取消 → 检查后代进程与残留文件. 证据: 拒绝记录、资源测量和清理结果. 未通过不开放生成代码执行.

### Gate C: 模型和文档能力可用

输入: 获准模型网关与脱敏文档. 步骤: 工具调用、结构输出、流式、图片理解、Embedding 与 OCR 样例验证. 证据: 能力表与质量样本. 不支持能力显式阻塞, 不以假接口替代.

### Gate D: 状态恢复成立

输入: 测试数据库与无副作用 runner. 步骤: 在持久化/启动/回写/审批等窗口注入进程退出, 验证 B28/B29/B38/B39/B23. 证据: 一次有效执行、UNKNOWN 可处理、无幽灵进程. 通过后再接入真实业务写操作.

以上是评审通过后获准实施的验证计划, 本轮未执行任何公司登录、真实压测或业务调用.
