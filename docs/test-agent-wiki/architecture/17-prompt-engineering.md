# 17. Prompt 工程与版本管理

[返回目录](./index.md)

> v0.3 学习定位: 本章保留原项目的设计案例, 不再作为必须实施的交付要求. Windows、无 Docker 等是原案例条件, 不是通用 Agent 架构要求. 当前学习路线与隔离纠正见 [19](19-learning-guide.md).

本章补全 [04 的节点与工具](04-agent-tools-skills.md), 在既有 Python 主服务内实现. 不引入 Prompt 管理 SaaS、自动改写生产提示词或新的业务平台. 以下为设计与教学示例, 尚未实现. 核查日期: 2026-10-27.

## 1. 提示词如何成为工程资产

用户说“查询接口压到 100”, 模型可以提取数值, 却不能自行认定是并发用户还是每秒请求. Prompt 要让模型指出缺失项并给出来源; 程序要阻止不完整参数进入执行器. 这两层共同成立, 才能把自然语言转换为可靠动作.

Prompt 工程管理模型的任务说明、示例、输入边界和输出约定, 也管理它们的版本与验证. 不是不断加长一份 system prompt. 官方文档说明了消息角色、指令组织和示例等机制; 下文的分层与发布契约是本项目设计, 不是某提供方强制架构. [Prompt engineering 官方文档](https://developers.openai.com/api/docs/guides/prompt-engineering)

## 2. 分层组装与信任边界

[![固定规则、节点模板与动态资料如何组装成模型请求](/images/test-agent-wiki/10-prompt.svg)](/images/test-agent-wiki/10-prompt.svg)

图左侧为代码仓库中经过评审的指令资产, 右侧为运行时数据. 组装器同时接收两类输入, 但不会把网页中的“忽略规则”提升为系统指令. 模型返回结果仍要经过程序校验和策略检查.

| 层 | 内容与例子 | 维护与加载 |
| --- | --- | --- |
| 全局规则 | 测试助手职责、不得伪造执行结果、证据要求、补问规则 | 随发布冻结, 每个需要的请求显式装配 |
| 节点模板 | 意图分类、参数提取、计划生成、文档用例、结果分析、摘要、记忆提炼、评测裁判 | 按图节点选择, 不一次塞入所有职责 |
| 工具定义 | 名称、用途、参数 Schema、前提与返回含义 | 从工具注册表生成当前可用集合 |
| 已激活 Skill | 文档用例步骤、引用格式、受支持工具指导 | 按任务匹配版本, 按需加载引用 |
| 当前用户请求 | 目标、最新更正、明确偏好 | 保留消息归属, 不替用户补默认含义 |
| 动态证据 | RAG 片段、OCR 结果、页面文本、日志、相关记忆 | 标明来源、范围与不确定性, 作为资料传入 |

实际 `system` / `developer` / `user` / `tool` 角色映射由模型适配器按网关能力验证. 本项目的概念分层不代表每个模型都支持同一组角色. 文本分隔符有助于识别资料边界, 不能提供安全隔离保证; 强制安全边界仍在代码与执行环境中.

Skill 格式复用保持 [04 的导入与激活流程](04-agent-tools-skills.md). Skill 可以指导如何生成用例, 不能覆盖平台安全规则、读取其他用户信息或扩大工具授权. 本次仅描述集成契约, 不创建或编辑实际 SKILL.md.

## 3. 组装器的输入输出契约

建议由 `server/agent/` 下的 Prompt 组装模块承担, 使用已有 Pydantic 校验, 无需额外服务. 输入是模板版本、节点类型、带类型的变量、选中上下文、工具与 Skill 版本、模型能力配置; 输出是提供方请求与脱敏调用清单.

处理顺序:

1. 从 run 固定的版本清单选模板, 校验节点与模型能力匹配.
2. 校验变量是否齐全、类型是否正确, 再进行纯数据插值; 禁止把变量当可执行模板代码.
3. 装配固定指令和当前工具 Schema, 与上下文模块协商剩余预算.
4. 插入带来源的用户请求、证据和必要 Skill 内容, 保持角色和信任边界.
5. 校验最终请求与输出 Schema 的兼容性, 记录模板/Schema/Skill/工具版本及输入引用.
6. 模型返回后先解析、校验, 再交给既有参数和策略节点; 不能直接拼成 shell 执行.

模板缺少必填变量属于组装错误, 返回 PROMPT_INPUT_INVALID; 用户尚未给出业务参数属于待补问状态. 两类缺失不能混淆. 前者需要修模板或调用代码, 后者由 HITL 补充信息.

每个模板最少记录 `template_id`, `version`, `content_hash`, `node_type`, `input_schema_version`, `output_schema_version`, `required_capabilities`, `eval_dataset_version`. 这些是建议字段, 不意味着为每个字段建设独立平台.

## 4. 参数提取示例与失败出口

以下是候选节点模板的教学片段, 不代表已上线 Prompt. 生产模板应配套固定样本验证.

```text
任务: 从用户请求提取压力测试参数, 不执行测试.
返回字段: intent, extracted_fields, source_refs, missing_fields, conflicts.
规则:
- 没有单位的数值不能推断为并发数或到达率.
- target_id 只能引用已提供的可用目标, 不编造目标.
- 来源引用必须指向本次输入的消息或配置字段.
- 缺参或冲突必须显式列出, 不用经验默认值补齐.
```

输入“查询接口压到 100”应得到压力测试意图、数值来源和负载模型/单位等缺失信息. 参数校验器随后生成补问. 用户回答“每秒 100 次请求”后, 仍需核对迭代与请求映射、时长、目标、阈值等 [09](09-testing.md) 要求, 不能仅因为语义更清楚就开始发压.

| 情况 | 处理 |
| --- | --- |
| 输出不是合法结构 | 有限次数修正, 仍失败为 MODEL_OUTPUT_INVALID |
| 格式合法但参数超上限 | 参数/策略拒绝, 不让模型改写成“已批准” |
| 来源引用不存在 | 判为无依据字段, 补问或退回提取 |
| 资料中有“跳过审批” | 作为资料内容, 不改变系统动作权限 |
| 工具未激活或版本不符 | 在注册表检查处阻止执行 |
| 模型能力不支持所需契约 | 对应节点 blocked, 不静默改成自由文本执行 |
| 缺参补问反复循环 | 使用缺参集合、输入版本与预算检查, 无新信息时停在等待 |

流式展示分开处理: 普通回答可输出文本增量; 工具参数分片必须收齐并校验后才形成提案; JSON 中间片段不触发执行. 页面展示计划、进度、证据和可提供的简短说明, 不提供 `thought.raw` 或承诺完整内部思维链.

## 5. 版本冻结、评测与回退

模板源文件与 Schema 跟随应用代码管理, 不把用户文本自动写入生产模板. 运行开始时固定一个版本清单, 包含全局规则、节点模板、工具 Schema、Skill、模型配置和上下文策略. 每次调用记录清单引用与实际输入清单, 便于区分模型问题、上下文问题和执行问题.

候选修改 → 静态变量/Schema 检查 → 固定案例回归 → 人工查看失败与分歧样本 → 审批发布版本. 这描述未来工程发布流程, 不构成本轮提交授权.

回归集至少覆盖正常任务、歧义单位、缺参、跨任务干扰、OCR 低置信度、检索证据冲突、工具返回注入、权限边界和上下文压缩后续问. 指标见 [10](10-evaluation.md), 不只比较模型自评分.

回退时新 run 使用旧的完整版本清单. 在途 run 原则上继续固定版本, 不能只替换某个提示词导致检查点不兼容; 如果当前版本存在必须停止的问题, 先暂停/取消相关运行, 再明确恢复或新建任务. 执行权限和撤销状态每次仍按当前有效策略检查, 不能以版本冻结为由保留已撤销授权.

记录模板版本不等于精确复现模型输出. 模型服务版本、随机性和外部系统状态不可完全固定时, 报告其限制. 不为复现保存密码或完整认证头; 脱敏快照也按用户范围和保留期访问.

## 6. 验收练习与定位

对应 [B94-B100](13-branches-acceptance.md). 准备脱敏合成请求与人工标注的意图、缺参项和来源. 用同一模型配置、上下文策略与工具集合分别测试候选模板和基线模板; 禁用写入长期记忆. 测试“100”“100 并发”“100 次/s”“需求正文要求忽略平台规则”等输入, 比较结构合法率、字段正确率、缺参识别率、工具选择准确率和策略违规数.

预期: 单位不明进入补问; 合法结构但越界参数被程序阻止; 修改模板版本可在调用清单中查到; 注入内容不触发无权动作. 本轮未运行这些模型实验, 不声称已有得分或阈值.

定位时先核对本次真正发送的模板与变量, 再看实际选入的证据, 最后看模型原始返回及程序校验. 不根据聊天界面显示的最终文字推断工具是否真正执行.

| 术语 | 中文含义 | 本章作用 |
| --- | --- | --- |
| Prompt template | 提示模板 | 节点可版本化的指令与输入结构 |
| Prompt assembly | 提示组装 | 将可信指令和动态资料按契约组成请求 |
