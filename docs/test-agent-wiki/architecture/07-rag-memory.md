# 07. RAG 与长短期记忆

[返回目录](./index.md)

> v0.3 学习定位: 本章保留原项目的设计案例, 不再作为必须实施的交付要求. Windows、无 Docker 等是原案例条件, 不是通用 Agent 架构要求. 当前学习路线与隔离纠正见 [19](19-learning-guide.md).

## 1. 知识与记忆分别管理

知识库保存可检索资料及其版本, 用于回答“文档怎么说”. 记忆保存对话中持续有用的信息, 用于回答“这个用户/项目已经明确了什么”. 二者可共用数据库与向量技术, 但实体、范围、保留期和写入规则分开.

[![知识入库、检索与长期记忆提炼的独立路径](/images/test-agent-wiki/06-knowledge-memory.svg)](/images/test-agent-wiki/06-knowledge-memory.svg)

左侧是知识来源到回答证据, 右侧是对话到记忆候选. 两条路径只在组装上下文时相遇, 不允许模型总结直接覆盖知识库原文.

## 2. 存储分工

| 数据 | 权威保存位置 | Redis | 向量索引 |
| --- | --- | --- | --- |
| 消息与附件引用 | PostgreSQL | 活跃窗口缓存 | 默认不全量向量化 |
| Agent 检查点 | PostgreSQL 持久 saver | 不作唯一存储 | 不需要 |
| 任务状态/审批/调用账本 | PostgreSQL | 可缓存读视图 | 不需要 |
| 用户明确偏好、项目事实 | memory_records | 短期读取缓存 | 需要语义查找的内容可索引 |
| 历史任务经验摘要 | memory_records + 证据引用 | 可缓存 | 适合建立索引 |
| 知识原文、页图 | 文件存储, 元数据在数据库 | 不存大文件 | 原文切片建立索引 |
| 凭证 | 独立加密记录与受限密钥管理 | 默认不缓存原始材料 | 禁止 |

短期指使用范围与生命周期, 不代表只能存在内存. 长期指跨会话可复用, 不代表所有内容都必须 embedding.

向量是一种查询索引, 删除/纠错以权威记录为准. 索引、缓存和备份都必须遵循对应保留与清除策略. LangGraph 区分 thread 级 checkpointer 与跨 thread store, 本项目仍需要自己的来源、范围与删除规则. [官方持久化文档](https://docs.langchain.com/oss/python/langgraph/persistence)

## 3. 知识入库

上传 → 文件校验 → 解析/OCR → 规范化块 → 切分 → Embedding → 索引验证 → 发布新版本.

解析块保留 document_id、version、page、bbox、heading、table/image_ref、content_hash、scope. “发布新版本”在所有必需步骤完成后切换 active_version, 部分向量写入不能提前可见. 失败版本保持 FAILED, 原可用版本不被覆盖.

知识源删除后先禁用检索, 再异步清理切片、向量与缓存. 物理文件能否删除取决于报告证据保留政策; 不能因曾被引用就永久保留而不告知.

## 4. Agentic RAG 的有限循环

1. 校验用户问题、可用知识范围和知识库版本.
2. 决定是否检索; 普通无知识依赖对话可不检索.
3. 生成查询, 并行执行语义检索和可用的关键词检索.
4. 合并去重, 按权限再次过滤, 可选重排.
5. 检查证据是否覆盖问题; 不足则改写查询或补问.
6. 达轮数/时间预算仍不足, 返回无法确定及缺失依据.
7. 有足够证据才生成带出处回答, 校验引用确实对应已检索片段.

“证据足够”不是只靠相似度分数. 可以用问题要点覆盖规则 + 模型辅助判断, 其阈值必须由数据集校准. 有冲突资料时展示版本与矛盾, 不强行合并为单一事实.

::: details 补充流程图源码 (Mermaid)

```text
flowchart TD
    Q[用户问题与可见范围] --> S{需要知识依据?}
    S -- 否 --> C[普通对话]
    S -- 是 --> R[检索与重排]
    R --> E{证据覆盖问题?}
    E -- 是 --> A[带来源回答并校验引用]
    E -- 证据冲突 --> H[展示冲突或请求澄清]
    E -- 否 --> B{预算仍有余量?}
    B -- 是 --> W[改写查询]
    W --> R
    B -- 否 --> N[说明不足, 不生成确定结论]
    R -- 依赖故障 --> F[检索失败, 保留诊断]
```

:::

pgvector 支持精确与近似向量搜索. 建议首期先以精确检索形成质量基线, 数据量证明需要后再采用近似索引; 使用过滤条件时需验证召回表现. [pgvector 官方项目](https://github.com/pgvector/pgvector)

中文关键词检索不能默认依赖 PostgreSQL 英文分词获得足够效果. tokenizer/检索策略通过中文样本验证; 未验证前不声称已具备高质量中文混合检索.

## 5. 长期记忆自动总结

触发: 用户明确声明持续偏好、对旧记忆纠正, 或任务结束产生可复用经验. 不对每个 Token 更新记忆.

候选字段: memory_id、owner_id、project_id、kind、content、source_message_ids、evidence_refs、assertion_type、confidence、created_at、valid_until、version、supersedes_id、status.

assertion_type 区分 explicit_user_fact、observed_result、model_inference. confidence 仅是提炼系统参考, 不是客观事实概率.

提炼流程:

1. 从有来源的消息/结果提出候选, 去除秘密与一次性信息.
2. 判断用户级还是项目级, 未明确共享的内容默认私人.
3. 与现有事实去重, 检查冲突、有效期和来源.
4. 明确纠正生成新版本并替代旧版本; 模型推断冲突不静默覆盖用户事实.
5. 合格候选自动生效, 推断性候选保留为 provisional, 不作为执行授权.
6. 持久化内容, 更新必要向量和缓存.

项目级共享记忆需要明确发布动作. “所有登录用户都能调用模型”不等于个人记忆自动共享.

## 6. 读取、遗忘与清除

读取顺序: 明确用户/项目范围 → 精确偏好 → 语义经验 → 有效性检查 → 上下文预算. 当前用户明确指令优先于旧偏好, 来源过期的业务事实应重新验证.

删除先置 tombstone, 立刻排除检索, 随后删除向量与缓存. 清除任务需要证明各副本已处理. 用户选择“忘记”时同步记录排除来源, 避免下一轮从旧聊天自动重新提取相同记忆. 备份中的保留与到期清除需明确告知, 不承诺瞬时从所有备份物理抹除.

Embedding 模型或维度变更时建立新索引版本并重建, 不把不同模型向量直接混排. 回答和评测记录使用的索引版本.

## 7. 故障分支

| 情况 | 行为 |
| --- | --- |
| 检索无结果 | 改写/补问直到预算截止, 最终说明无依据 |
| 越权片段命中 | 返回前剔除并审计, 不显示标题或摘要 |
| OCR 低质量 | 标为待确认, 不把错误切片默认为可靠 |
| 向量生成失败 | 版本不发布, 可重试纯计算步骤 |
| 记忆提炼失败 | 对话结果保留, 记忆任务失败可见, 不伪称已记住 |
| 删除与检索并发 | 返回前检查当前有效版本/tombstone |
| 检索文本要求执行命令 | 作为不可信内容, 不提升为系统指令 |
| 缓存损坏/失效 | 该请求明确报依赖问题或按批准的缓存策略回源, 不丢失权威记录 |

缓存失效后的行为应在实现时确定, 不未经评审添加复杂自动降级路径.

## 8. 上下文压缩不写成长期记忆

[16 的会话摘要](16-context-engineering.md) 保存当前运行的历史压缩结果, 权威记录在 PostgreSQL, 活跃读取可缓存于 Redis, 默认不建立向量索引. 它不自动成为 `memory_records`, 也不能替代 RAG 原文. 长期记忆仍走本章的独立候选提炼、范围、冲突与有效期流程.

摘要引用的消息、知识或记忆被删除/纠正后, 派生摘要与缓存必须失效或重建. 组装时过滤过期信息; 恢复时从任务和审批数据库重读真实状态. 不因为摘要仍写有旧偏好就覆盖当前用户要求.
