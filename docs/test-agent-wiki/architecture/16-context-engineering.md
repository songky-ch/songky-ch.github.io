# 16. 上下文工程与压缩

[返回目录](./index.md)

本章补全 [04 的 load_context 节点](04-agent-tools-skills.md), 与 [07 的知识和记忆](07-rag-memory.md) 配合. 不新增业务能力或独立服务. 以下为建议实现与待实施验收, 不是已运行代码. 核查日期: 2026-10-27.

## 1. 压缩解决什么, 没有解决什么

一次 UI 专项测试可能产生几十轮对话、页面截图、DOM 摘要和大量日志. 把它们全部放进每次请求, 会挤占输出空间, 也会让关键约束淹没在旧信息中. 上下文工程负责决定这一轮模型看到哪些信息、以什么形式看到, 以及缺少细节时如何找回.

模型摘要是其中一种手段, 并不低级. 真正需要避免的是“把全部历史反复总结成一段话, 再让这段话替代原始事实”. 本项目采用程序筛选与裁剪、结构化摘要、按需回查的组合.

| 概念 | 本项目职责 | 不能替代 |
| --- | --- | --- |
| Context engineering / 上下文工程 | 选择、组织、预算、更新模型输入 | 执行权限与数据库状态 |
| Compaction / 上下文压缩 | 缩减当前运行携带的历史, 保留继续工作的必要信息 | 原始证据与审批记录 |
| Memory / 长期记忆 | 跨会话复用用户偏好和可追溯经验 | 当前任务真实状态 |
| RAG / 检索增强生成 | 从可见知识版本获取问题相关证据 | 完整会话历史 |
| Prompt caching / 提示缓存 | 在提供方支持时复用计算, 降低重复前缀成本或延迟 | 上下文容量控制与内容筛选 |

## 2. 输入分层与预算

[![上下文从权威数据到模型输入的分层与预算边界](/images/test-agent-wiki/09-context.svg)](/images/test-agent-wiki/09-context.svg)

从上方的当前任务读起. 必需信息先占预算, 历史、知识和日志再按相关性进入. 超预算不会直接删除用户约束, 而是先减少可选材料. 原始日志仍由产物引用访问.

每次调用按实际模型能力计算: 可用输入预算 = 上下文上限 - 输出预留 - 协议与计量余量. 推理 Token 如何占用窗口和输出额度以网关实测为准, 不机械套用统一公式. 工具 Schema、图片、附件也需要计量; 不用字符数冒充精确 Token 数. 模型切换必须重新计算.

| 信息层 | 内容 | 处理方式 |
| --- | --- | --- |
| 固定规则 | 当前批准版本的角色、行为规则、节点输出契约 | 不由摘要模型改写 |
| 当前任务必需项 | 当前目标、用户约束、已验证参数、计划版本、真实任务状态、待处理交互引用 | 以结构化记录重建, 保留来源 |
| 协议必需项 | 尚需处理的工具调用及其关联结果 | 按提供方协议保留完整关联 |
| 近期交互 | 最新用户要求、最近有用的消息与结果 | 优先保留原文; 用户更正必须生效 |
| 选择性材料 | 已验证摘要、范围内记忆、RAG 片段、所选 Skill | 相关性、有效性、来源与分区预算共同筛选 |
| 大型证据 | 全量日志、DOM、截图、OCR 页图、trace | 文件归档; 输入摘要、必要局部和证据引用 |

预算配置随模型与节点版本冻结, 包含输出预留、触发水位、分区上限、历史回查上限、摘要调用次数和时限. 首期不设未经测量的通用百分比. 必需项本身超过窗口时, 返回 CONTEXT_REQUIRED_TOO_LARGE, 由用户拆分任务或按批准配置处理; 不能悄悄丢弃关键要求.

## 3. 一次组装如何实现

1. `load_context` 从认证上下文获取用户与项目范围, 读取当前消息版本、run 检查点、任务和交互记录.
2. 检查所有候选资料的所有者、有效版本和删除状态; 缓存键包含范围与版本, 不仅是问题文本.
3. [Prompt 组装器](17-prompt-engineering.md) 提供固定规则、节点契约与所需工具目录, 先计算固定开销.
4. 加入当前目标与约束、必要协议项、近期消息; 再选择相关摘要、知识、记忆与 Skill 引用.
5. 工具适配器把大结果投影为领域结构: 压测保留测量窗口、负载模型、指标、错误样本和结果完整度; UI 保留步骤、断言、失败位置和截图引用.
6. 超预算先去重、移除已失效或无关材料、减少可选片段. 仍不足时对已闭合历史生成结构化摘要.
7. 校验最终请求大小、Schema 与来源有效性, 保存脱敏清单和版本, 才调用模型.

裁剪规则必须同时保留负面证据, 不能只取成功请求或日志开头. 文档用例生成中的需求编号、流程分支、未解析页和 OCR 不确定性不能被裁剪成“需求已完整理解”. 若模型需要原文, 经带范围校验的历史/产物读取工具分页取回, 回查也受总预算约束.

## 4. 结构化摘要与并发控制

摘要覆盖已闭合的消息区间, 不覆盖仍在等待结果的工具交换. 触发点是阶段完成或接近输入预算, 不是每输出一个 Token. 原始消息按原保留策略保存, 摘要不删除原文.

建议 `context_summaries` 保存: `id`, `run_id`, `scope`, `source_message_range`, `source_version`, `source_hash`, `summary_schema_version`, `model_config_ref`, `prompt_version`, `parent_summary_id`, `content`, `status`, `created_at`.

`content` 至少包含目标、用户约束及原文引用、已验证事实及证据、已完成步骤、未解决问题、相互冲突的说法、产物引用. 推断与事实分别标识. 审批只放引用, 不把“用户允许”一句话作为授权证明.

摘要流程为候选生成 → 结构与引用校验 → 对照必保字段 → 按消息版本 CAS 激活. 校验器能确定的字段使用规则比较; 语义遗漏通过标注集与抽查验证, 不声称规则能证明所有语义等价. 生成过程中有新消息或用户更正, 旧候选不得覆盖新状态.

连续压缩时保留来源范围与摘要链. 当发现矛盾、关键事实无出处或达到经评测确定的重建条件, 从原始记录重建, 不只对上一次摘要继续概括. 旧摘要保留为历史版本, 不同时作为当前事实使用.

::: details 补充流程图源码 (Mermaid)

```text

    B -- 是 --> C[校验协议与来源后调用模型]
    B -- 否 --> D[去重并裁剪可选材料]
    D --> E{仍超预算?}
    E -- 否 --> C
    E -- 是 --> F{存在可压缩的闭合历史?}

    F -- 是 --> H[生成摘要候选并校验]

    J --> K{可容纳必需上下文?}
```

原生压缩是可选适配能力. OpenAI 的独立 compact 接口返回的窗口可能包含不可读的压缩项和保留项, 必须按该接口约定整体传回, 不能当普通摘要文本解析或自行删改. 公司网关尚未验证支持, 首期基线不依赖它. [官方 Compaction 文档](https://developers.openai.com/api/docs/guides/compaction)

## 5. 存储、恢复与敏感信息

| 数据 | 保存方式 | 读取规则 |
| --- | --- | --- |
| 原始消息/任务事实 | 既有 PostgreSQL 实体 | 受用户范围、版本、保留策略约束 |
| 摘要与输入清单 | PostgreSQL 元数据, 大型脱敏快照放产物目录 | 清单记录选择/省略原因及来源, 不默认向量化 |
| 活跃组装缓存 | Redis, 带 TTL 与范围/版本键 | 可丢失, 必须能由权威记录重建 |
| 大型原始工具输出 | 既有 artifacts 与文件目录 | 按需读取, 不公开任意路径 |

Token、密码和原始认证材料不得进入摘要、Embedding、Prompt 快照或日志. 用户删除/纠正来源时, 关联摘要和缓存失效; 旧清单可保留脱敏审计元数据, 删除内容不能继续出现在恢复上下文中. “可复现”不能凌驾于删除和保留规则.

恢复时先核对任务、审批和消息版本, 再使用有效摘要. 即使摘要写了“已批准”, 数据库授权过期仍必须等待新的有效授权. 该步骤由 Harness 执行, 不交给模型判断.

## 6. 分支与验收练习

对应 [B86-B93](13-branches-acceptance.md). 教学练习不调用公司接口: 准备一份脱敏合成会话, 包含“仅测试环境、最多 10 次/s、不得提交订单”、三轮大日志、一次用户更正、一个待审批动作和一条无关旧记忆.

步骤: 人工标注必保事实及出处 → 生成压缩前输入 → 运行候选压缩策略 → 检查更正和待审批状态 → 追问旧日志细节并回查 → 注入摘要生成失败与来源删除 → 比较结果. 本轮仅设计练习, 尚未执行.

验收证据: 每次输入清单、Token 计量来源、摘要版本、保留/遗漏标注、原文回查结果和状态变化. 指标见 [10](10-evaluation.md): 关键约束遗漏率、事实保留率、任务成功率差异、摘要错误率、成本与延迟. 缺少事实标签时不计算事实保留率. 压缩率只衡量体积, 不能证明质量.

定位顺序: 输入清单没选中资料 → 调整选择规则; 摘要丢失事实 → 检查压缩模板和验证; 事实已在输入但模型忽略 → 检查节点 Prompt 与模型能力; 事实正确却越权执行 → 检查 Harness, 不靠继续加提示词修复权限漏洞.
