# 09. 接口、UI 与压力性能测试

[返回目录](./index.md)

## 1. 专项测试共用什么

表单与自然语言最终都生成同一 TaskSpec: task_type、target、environment、parameters、credential_ref、assertions、stop_policy、artifact_policy、config_version. 前端校验改善体验, 服务端校验才是权威.

::: details 补充流程图源码 (Mermaid)

```text
flowchart TD
    F[页面表单] --> V[领域参数校验]
    C[用户描述] --> X[模型提取和缺参补问]
    X --> V
    V -- 不合法 --> Q[显示缺失或冲突]
    Q --> V
    V -- 合法 --> P[策略与审批]
    P -- 拒绝 --> R[REJECTED]
    P -- 等待 --> H[人工介入]
    H --> V
    P -- 允许 --> T{任务类型}
    T -- 接口 --> A[接口套件 runner]
    T -- UI --> U[Playwright runner]
    T -- 负载 --> L[k6 runner]
    A --> E[归档证据与规则判定]
    U --> E
    L --> E
    E --> G[模型解释结果]
    G --> O[报告: 状态 / 结论 / 缺失项]
```

:::

每类任务还有失败、取消和超时出口, 统一服从 [任务状态机](05-tasks-executor.md), 领域分支见下表.

## 2. 接口测试套件

采用结构化套件描述业务步骤, 程序生成/调用 pytest 与 HTTPX 执行. 数据提取使用受限表达式, 不允许在配置里执行任意 Python eval.

| 配置 | 含义 |
| --- | --- |
| environment / base_url | 已登记的目标环境, 不从模型文本随意创建 |
| steps / depends_on | 步骤与依赖 DAG, 预检拒绝循环依赖 |
| method / path / headers / body | 请求参数, 秘密头由凭证模块注入 |
| extracts | 从响应取业务 ID, 带类型与缺失处理 |
| assertions | 状态码、schema、字段、业务结果 |
| data_sets | 参数化数据, 明确敏感数据处理 |
| timeout / retry_policy | 超时与安全重试条件, 写请求默认不自动重试 |
| cleanup | 用户明确允许的清理动作, 本身也是需授权操作 |

失败分支: 前置失败则依赖步骤 SKIPPED; 独立步骤是否继续由套件策略确定. 某步骤请求已发送但结果未知则标记 UNKNOWN 并停止依赖步骤. 清理失败独立记录, 不覆盖原始失败. 只测已批准环境, 重定向也必须重新校验目标范围.

套件报告包括每步请求摘要、脱敏响应、断言结果、耗时、依赖跳过原因和清理结果. 不默认存储完整敏感报文.

## 3. UI 页面分析与脚本

流程: 输入页面与目标 → 验证服务器侧登录 → Linux 浏览器采集可访问性/DOM 信息和截图 → 模型拟定步骤与定位器 → 生成脚本 → 规则检查与审批 → 隔离执行 → trace/截图/断言 → 报告.

“页面探查”也可能触发页面加载请求, 不能视为绝对无副作用. 探查权限默认不含提交表单、付款、删除、上传等操作. 这些动作进入明确执行计划.

优先稳定、面向用户语义的 locator, 必要时使用经确认测试标识. 不以固定 sleep 和坐标点击作为首选. iframe、弹窗、新页、文件下载、验证码和 MFA 是独立分支; 需要人介入的内容回到 HITL, 不绕过验证.

脚本生成与脚本执行是两个工具. 修复脚本会改变哈希, 必须重新校验审批; 失败后只允许有预算的修复, 不能不断删除断言直到“通过”. 脚本输出必须包含可验证断言.

Playwright 可用认证状态启动隔离 browser context, 但状态文件含敏感材料, 不是普通报告. WebView2 到 Playwright 的状态转换与跨机器有效性必须实际验证. [认证文档](https://playwright.dev/python/docs/auth)

Linux 浏览器二进制与 Playwright 版本要配套, 系统依赖必须在部署前检查. Linux Chromium 测试不代表验证了 Windows Edge 特定环境. [浏览器文档](https://playwright.dev/python/docs/browsers)

## 4. 压力与性能参数

| 参数组 | 必须明确的字段 |
| --- | --- |
| 目标 | target_id、环境、场景、接口/业务事务 |
| 负载模型 | 固定并发 / 阶梯并发 / 固定到达率 / 阶梯到达率 |
| 强度 | VU 数量或迭代到达率, 单位、上限 |
| 时间 | 预热、升压阶段、稳态、降压、总截止时间 |
| 请求行为 | think time、连接/请求超时、数据集、关联取参 |
| 业务断言 | 成功响应定义, 业务错误与 HTTP 错误区分 |
| 通过阈值 | 各场景响应时间分位数、错误率、吞吐目标 |
| 停止条件 | 错误率/延时/资源上限、持续窗口、人工停止 |
| 监控 | 指标源、查询范围、采样间隔、目标标签 |
| 凭证 | 身份类型、有效期、共享同一账户的限制 |

并发用户数不等于 QPS. k6 到达率控制的是迭代, 一次迭代可能有多次请求, 所以不能把 100 iterations/s 直接报告为 100 requests/s. 开放/封闭负载模型应按测试目标选择. [k6 负载模型](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/)

唯一工号只是人员登录规则, 不代表一个账号适合模拟大量业务用户. 使用同一身份压测时需明确会话互斥、每用户限流、业务数据冲突与代表性限制. 如必须多测试身份而尚无授权账号池, 该场景保持阻塞, 不虚构账号.

## 5. 指标和判定

| 指标 | 解释与注意 |
| --- | --- |
| achieved request rate | 实际请求数 / 有效测量时长, 与设定到达率分别展示 |
| p50 / p95 / p99 | 测量窗口内延时分布, 明确是否排除预热 |
| error_rate | 错误请求数 / 总请求数, 分开传输、HTTP 与业务错误 |
| dropped_iterations | 负载生成器没能启动的迭代, 影响测试有效性 |
| checks / thresholds | 业务检查和整体阈值分别判断 |
| generator resources | 压测机 CPU、内存、网络、文件描述符, 判断发压端瓶颈 |
| target resources | 目标 CPU、内存、GC、连接池等, 仅在有监控数据时报告 |

阈值由业务目标决定, 不能预设所有系统 p95 < 200ms. k6 阈值可决定测试是否失败, 但应用仍需将“阈值失败”与“引擎启动失败”映射到不同结果. [k6 thresholds](https://grafana.com/docs/k6/latest/using-k6/thresholds/)

按场景先保留原始指标或可合并直方图. 不把多个批次的 p95 简单平均作为总体 p95. 同时报告样本数、有效测量时长、预热处理与负载达成情况.

## 6. 发压与主服务共机的局限

虽然部署在同一 Linux 服务器可满足初期要求, 发压会争用主服务 CPU、网络与磁盘. 必须保留主服务资源, 检查 generator 饱和状态. 达不到目标负载时结果标记 INCONCLUSIVE, 不据此断言被测系统极限.

单机无法证明需要分布式规模的容量. 超出经验证容量的任务拒绝并说明限制, 不未经确认增加机器或迁移到用户电脑.

## 7. 领域异常表

| 场景 | 去向 |
| --- | --- |
| 缺少负载单位/测试环境 | WAITING_INPUT |
| 审批后脚本或目标改变 | 重新预检与审批 |
| 登录失效 | 停止新业务动作, 保存事实, WAITING_AUTH 或结束无效 attempt |
| API 返回断言错误 | 执行完成, verdict=FAIL |
| UI 定位器失效 | 保留截图/trace, 限次修复或失败 |
| UI 操作结果未知 | UNKNOWN, 禁止直接重放业务提交 |
| 压测触发停止阈值 | 终止发压, 记录 FAIL/INCONCLUSIVE 的明确规则 |
| 目标监控缺失 | 保留客户端指标, 对根因标记证据不足 |
| 发压机饱和 | INCONCLUSIVE, 展示资源证据 |
| 报告模型失败 | 原始结果仍可用, report_status=failed, 可单独重试报告 |

## 8. 报告契约

报告固定包含目标、配置版本、时间窗口、身份脱敏引用、工具版本、执行状态、测试结论、指标、断言、证据链接、缺失与限制. 模型只补充解释与有依据的假设, 不重写测量数值. 推断根因必须标为推断, 引用支持它的监控或 trace.
