# 12. 无 Docker 部署与运维

[返回目录](./index.md)

## 1. 部署拓扑

::: details 补充流程图源码 (Mermaid)

```text
flowchart TB
    W[Windows 客户端] -->|HTTPS| G[公司网关或已确认 TLS 入口]
    G --> A[一个 FastAPI/Uvicorn 主进程]
    A --> P[(PostgreSQL + pgvector)]
    A --> R[(Redis)]
    A --> F[持久文件目录]
    A --> M[公司模型网关]
    A --> S[受限 OS launcher / systemd]
    S --> E[每任务独立 runner 与资源组]
    E --> T[允许的被测系统]
    A --> O[现有监控与日志设施]
```

:::

一个业务主进程不包含 PostgreSQL、Redis、systemd 这些基础设施. 不需要运行独立前端开发服务器或常驻独立 Worker. systemd 任务单元与主服务的停止关系必须经过验证.

首期 Uvicorn 配置为一个 worker, 因为调度循环驻留其中; 增加 worker 之前必须重新设计调度所有权, 不能直接调大参数. FastAPI 文档说明 worker 是多个进程, 不共享普通进程内状态. [官方部署文档](https://fastapi.tiangolo.com/deployment/server-workers/)

## 2. 目录与权限建议

| 目录职责 | 内容 | 访问原则 |
| --- | --- | --- |
| release | 后端代码、静态前端、锁定依赖清单 | 主服务和 runner 只读 |
| config | 非秘密配置与策略版本 | 运维写, 应用只读 |
| secrets | 数据库/模型/加密密钥 | 仅主服务所需权限, runner 不可读 |
| data/artifacts | 上传原文、正式报告与证据 | 通过授权接口访问 |
| data/tasks/{task}/{attempt} | 任务输入输出和临时文件 | 每任务隔离 |
| logs | 脱敏结构化日志 | 有保留上限 |
| browser-cache / ocr-models | 预装二进制与模型文件 | 只读, 版本与哈希可查 |

实际绝对路径由运维环境确定. 不在用户上传字段里接受服务器路径, 不允许 runner 访问其他任务目录.

## 3. 系统隔离配置要求

控制项包括非 root 身份、禁止提权、只读系统文件、独立临时目录、任务资源组、CPU/内存/进程数限制以及目标网络限制. 具体 systemd 指令取决于服务器版本与浏览器兼容性, 不能照搬最新手册全部选项.

NoNewPrivileges 防止进程通过执行程序获得新权限, 并不自动阻止读取同权限秘密或访问网络. cgroup 控制资源消耗, 不替代凭证与数据范围检查. [执行环境文档](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html), [资源控制文档](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html)

任务出站策略应在实际连接层生效, 包含重定向和 DNS 解析变化. 浏览器会请求页面子资源, 所以目标配置必须包含获准业务域与必要静态资源域, 不能仅检查起始 URL. 不允许访问云元数据、数据库、主服务内部管理入口或其他未授权目标.

若要通过 systemd 动态创建任务, launcher 必须只接受预定义 runner、资源 profile 和平台分配目录, 不能接受任意 unit 文件、用户 ID、挂载点或执行命令. 这项需要运维确认后形成实际配置, 本稿不交付未经验证的高权限脚本.

## 4. 启动、停止与发布

启动: 配置/版本校验 → 数据库连接与 schema 校验 → 必需依赖检查 → 调度所有权 → 遗留任务对账 → 标记就绪.

停止: 停止接收新执行任务 → 停止认领 → 保存状态 → 在明确窗口内完成或停止任务 → 回收进程树 → 关闭连接. “无限等正在运行压测结束”不是可控停机策略.

发布前冻结版本清单, 备份数据库与文件. 数据库迁移由运维发布步骤单独执行, 不让每个应用启动偷偷迁移. 旧检查点、Skill 版本和任务配置须能识别; 不兼容的等待任务标记需处理, 不强行用新代码恢复.

回滚要验证 schema 兼容; 不承诺回滚二进制就能撤销数据库迁移. 生产配置、秘密与代码分别管理. 当前阶段不实现自动升级渠道.

## 5. 可观测性

贯穿 request_id、conversation_id、run_id、task_id、attempt_id、tool_call_id 和 trace_id. 结构化日志记录状态变化、耗时、错误码与证据引用, 不记录秘密、完整内部推理或无必要的原始业务报文.

| 对象 | 必备指标 |
| --- | --- |
| API | 请求量、错误率、延时、活跃连接 |
| Agent | 模型耗时、调用数、预算使用、结构错误、循环上限 |
| 任务 | 排队时长、活跃数、租约失联、UNKNOWN 数、取消耗时 |
| 执行器 | CPU、内存、进程数、输出字节、磁盘占用 |
| HITL | 待处理数、等待时长、过期与冲突 |
| RAG | 检索延时、无命中率、索引版本与失败数 |
| 评测 | 总/完成/错误/不可计算样本数、裁判分歧 |

OpenTelemetry 统一追踪、指标和日志的关联方式, 不意味着安装 SDK 就自动有存储与查询平台. 现有收集后端若不可用, 在部署清单中明确缺失. [信号概念](https://opentelemetry.io/docs/concepts/signals/)

目标监控通过已授权只读查询获取, 明确时间窗口、标签和采样步长; Prometheus 接口是候选集成方式. [HTTP API](https://prometheus.io/docs/prometheus/latest/querying/api/)

## 6. 容量与 SLO 不能编造

需要实测后填写: 并发用户、SSE 连接数、每类任务并发、文档页数/大小、最大 UI 浏览器数、最大负载能力、每任务日志上限、数据库连接池、模型配额.

初期生产配置必须有有限值, 由环境和测试决定. 缺值应启动校验失败或相应能力 unavailable, 不默认为无限. 文档不声称支持某个 TPS、千人并发或“99.99% 可用”. 单机是已知单点, 与多机高可用不同.

## 7. 备份、保留与恢复

数据库、文件与必要密钥恢复材料分别备份并关联版本. 定期在隔离环境演练恢复, 校验文档引用、审批记录、记忆 tombstone、任务结果和文件哈希. 恢复旧备份后重放删除/撤销记录, 避免已删除记忆或授权重新生效.

RPO/RTO、日志/文档/报告保留期待公司要求确认. 备份不能作为无限保留所有敏感数据的理由. Redis 不存唯一事实, 但清空缓存后的系统行为仍需验证; 不把缓存重建当成已完成灾备.

## 8. 依赖故障策略

数据库不可用: 停止新任务与新的副作用步骤, 运行负载按失联截止策略停止; 尽可能保留局部证据, 重连后对账. 不继续无账本执行.

模型不可用: 不生成新的计划; 已批准、无需模型介入的确定性任务可以按既定计划完成, 报告解释单独标失败. 这不是模型替换或自动降级.

Redis 不可用: 首期按明确依赖策略暂停需要它的入口/限流路径; 是否允许数据库回源需专项评审, 本稿不默认实现双套逻辑.

磁盘不足: 停止接收大文件与新任务, 终止将无法留存证据的执行; 不删除其他用户文件“腾空间”.
