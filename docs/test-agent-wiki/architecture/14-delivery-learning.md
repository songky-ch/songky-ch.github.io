# 14. 开发顺序与文档规范

[返回目录](./index.md)

## 1. 评审顺序

先确认 01 的边界与决策提案 → 03 的身份可行性 → 05/06 的执行与审批 → 07/08 的知识与文档 → 09/10 的测试与评测 → 11/12 的契约与部署.

方案冻结记录必须包含接受的决策 ID、修订版本、仍待验证的条件以及被阻塞的能力. 不要求所有远期问题一次解决, 但不能在核心身份和执行边界不成立时宣称方案完全落地.

## 2. 分阶段开发建议

| 阶段 | 实现范围 | 必须交付的 Wiki/证据 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| P0 可行性验证 | 四个 Gate, 确定具体版本 | 环境、输入、观察、失败原因、决策更新 | 核心约束有可执行方案 |
| P1 基础骨架 | 身份、会话、事件、任务、HITL、产物、执行器 | 一次请求时序、数据库事务、取消恢复记录 | 无副作用任务完整跑通且可恢复 |
| P2 Agent 核心 | 通用对话、工具、参数、预算、检查点 | 模型调用链、节点职责、工具契约 | 缺参/拒绝/失败均有正确出口 |
| P3 文档与知识 | OCR/视觉、Skill 用例、RAG、长短期记忆 | 文档来源映射、记忆冲突与删除证明 | 样本文档和范围隔离达标 |
| P4 专项测试 | 接口 → UI → 负载与性能 | 每种 runner 的输入、脚本、证据、报告 | 隔离、审批、指标有效性达标 |
| P5 评测能力 | 自有/外部 KB 适配、数据集、评分与对比 | 样本来源、指标公式、裁判校准、复现报告 | 指标分母、N/A、错误都正确 |
| P6 内部试用 | 备份恢复、容量、发布、用户操作说明 | 运行手册与试用问题清单 | 目标环境验收通过 |

每阶段交付后评审再进入下一阶段. P3/P4 的先后可由你决定, 不是现在开始排期. 不给未经估算的人日或完成日期.

## 3. 未来代码目录示意

以下仅说明职责, 本轮不创建这些业务目录或代码.

```text
client/windows/         Windows 壳与受控浏览器桥
client/web/             工作台
server/api/             HTTP 与事件接口
server/identity/        平台身份与目标凭证
server/agent/           图节点、上下文、模型适配
server/policy/          授权范围与人工介入
server/tasks/           状态、调度、租约和对账
server/tools/           工具注册与领域适配
server/knowledge/       文档索引与检索
server/memory/          提炼、冲突、读取与删除
server/evaluation/      数据集、目标适配、评分
runners/                受限执行入口与结果协议
migrations/             数据库迁移
wiki/                   架构、调用链、操作与验证记录
```

不为每个目录再引入通用插件框架. 工具 schema 和 TaskSpec 是必要边界, 其余抽象以出现实际重复为依据.

## 4. 每个核心模块的 Wiki 内容

1. 解决什么问题, 不负责什么.
2. 实际入口文件、函数、调用者与被调用者.
3. 输入输出、数据库读写、外部调用和事务边界.
4. 正常路径、补问、拒绝、异常、取消和重启路径.
5. 一条脱敏请求从进入到产出的完整追踪.
6. 可执行环境准备、验证步骤、预期与实际结果.
7. 已知限制、版本和来源.

代码开始后, 本文中的建议路径要替换为真实链接, 不能保留虚构函数当实现说明. 文档变更跟随功能提交, 不在项目结束才补写.

## 5. 核心注释规则

注释解释不直观的设计原因, 例如“为什么中断前不发业务请求”“为什么必须先核对旧 attempt”“为什么缺上下文不能计算忠实度”. 类型清楚、名称直观的赋值不逐行翻译.

副作用、幂等、审批绑定、检查点重放、事件顺序、记忆冲突和指标分母是重点注释位置. 使用与代码一致的术语, 不加入 TODO/FIXME 标记, 不顺手修改无关已有注释.

## 6. 学习验收问题

| 问题 | 应能给出的解释 |
| --- | --- |
| 模型输出了工具调用, 为什么还没执行? | 需注册表、参数、策略与调度校验 |
| 为什么唯一工号不能解决服务端登录? | 工号是声明, 服务端需要验证其真实身份 |
| 为什么 Redis 不保存唯一短期记忆? | 短期作用域不等于可丢失, 恢复依赖持久记录 |
| 为什么租约到期不能立刻重跑? | 旧进程可能仍执行且副作用未明 |
| 人工批准之后还有什么检查? | 动作/参数/脚本/目标/时间/身份是否仍匹配 |
| 为什么 RAG 评测不能只看总分? | 不同可观察层、分母与标签前提不同 |
| 为什么子进程不是沙箱? | 可能继承同身份文件与网络权限 |
| 为什么模型报告失败不重跑压测? | 报告和测试独立, 真实测量结果已存在 |

本项目仅包含用户要求的 Wiki, 不附加面试专题. 用户后续已授权在现有站点新增独立公开栏目.
