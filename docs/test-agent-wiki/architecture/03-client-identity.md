# 03. Windows 客户端与身份

[返回目录](./index.md)

## 1. 两个浏览区域, 两条信任链

建议 Windows 壳包含工作台与内网浏览两个隔离区域. 工作台加载平台自己的 HTTPS 页面, 内网区域展示公司允许访问的网页. 内网页面不能调用工作台的文件、凭证和宿主能力.

用户在公司登录页手动输入凭证. 平台不收集密码, 不往页面注入键盘监听, 不把浏览器存储目录作为通用凭证包上传.

| 信任链 | 需要回答的问题 | 可信依据 |
| --- | --- | --- |
| 平台身份 | 谁正在使用 Agent | 后端可验证的公司身份结果 |
| 业务访问 | Agent 可代表谁访问哪个系统 | 针对目标系统有效且获准使用的会话/凭证 |

平台登录成功不代表拥有所有业务系统权限; 每人唯一工号也不能替代后端验证. 暂不做不同模型权限等级, 但每个查询与文件下载仍须按用户/共享范围过滤.

## 2. WebView2 的明确限制

Microsoft 文档明确反对用内嵌浏览器展示 OAuth 登录页后抓取重定向、Cookie 等获取 Token. 因此“没有 client_id 就抓 Token”不能成为本项目已经成立的认证方案. 本稿保留 WebView2 作为产品入口, 公司实际登录协议、允许的集成途径和服务端验证接口是 Q01/Q02 阻塞项. [官方说明](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/webview2)

若公司提供获准的业务会话复用机制, 才设计目标凭证适配器. 若没有可用机制, 对应登录或远程执行能力明确标记 BLOCKED, 不假冒身份、不关闭校验、不偷偷回到用户电脑运行任务.

## 3. 登录与凭证流程

[![登录验证与业务凭证检查的成功、失败和阻塞分支](/images/test-agent-wiki/02-identity.svg)](/images/test-agent-wiki/02-identity.svg)

阅读时先区分“公司登录完成”和“平台后端验证完成”. 只有后者成功才建立平台用户会话. 业务凭证不可复用时, 用户仍可在已通过平台身份验证的前提下使用不依赖该凭证的能力; 依赖凭证的任务保持阻塞.

| 分支 ID | 条件 | 处理 |
| --- | --- | --- |
| A01 | WebView2 Runtime 不可用 | 明确缺失依赖, 不进入空白登录页 |
| A02 | IDaaS 拒绝内嵌登录 | 阻塞集成, 确认公司批准的方式 |
| A03 | 用户取消登录/MFA 未完成 | 保持未登录, 不创建平台会话 |
| A04 | 客户端声称登录成功, 后端无法验证 | 拒绝创建平台会话 |
| A05 | 后端验证成功 | 绑定不可变公司主体 ID, 创建平台会话 |
| A06 | 业务凭证跨机器验证成功 | 保存受限凭证引用, 不进入模型上下文 |
| A07 | 设备/IP/应用绑定导致 Linux 验证失败 | 相关能力阻塞, 不反复重放登录 |
| A08 | 会话过期且用户在线 | 请求重新认证, 重新校验待执行动作 |
| A09 | 会话过期且用户离线 | WAITING_AUTH, 达等待期限后 EXPIRED |
| A10 | 收到权限拒绝 403 | POLICY/ACCESS 错误, 不自动当成过期刷新 |
| A11 | 主动退出平台 | 撤销平台会话和未使用授权, 相关运行任务按停止策略终止 |

## 4. 平台会话与凭证记录

建议平台使用服务端可撤销的 opaque session, 前端通过 Secure/HttpOnly/SameSite Cookie 访问同源 API. 原生客户端与 WebView2 的会话建立方式要随 Q01 验证, 不在 URL 中携带会话令牌. 有状态写操作校验 CSRF/Origin, 日志不记录 Cookie.

凭证记录包含 credential_ref、owner_id、target_id、scope、expires_at、status、key_version 和加密后的材料. 密钥与数据库分开保管. 模型、Skill、事件流只看 credential_ref 与状态.

执行时凭证按目标临时注入受隔离的 runner. 不用命令行参数携带秘密, 不继承主服务完整环境变量. UI 的登录状态文件属于秘密材料, 不能进入普通产物下载. 凭证刷新只使用身份系统支持且获准的方式; 无 refresh 能力时必须重新认证.

## 5. 桌面桥与前端页面

宿主桥只暴露有限消息: 打开允许的内网页面、通知登录流程状态、选择上传文件、接收安全下载. 每条消息验证 origin、类型、大小和 schema, 不提供任意执行脚本/任意文件读取/任意 HTTP 代理.

WebView2 安全指导要求校验页面来源和消息, 并避免通用代理接口. [安全文档](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security)

工作台最小页面:

- 对话页: 消息、附件、计划摘要、工具进度和人工介入卡片.
- 任务页: 状态、参数、实时事件、取消与证据.
- 专项配置页: 与自然语言入口共用 schema.
- 知识库页: 数据源、版本、入库状态、检索预览.
- 记忆页: 当前记忆、来源、纠正和删除.
- 评测页: 目标、数据集、指标、样本明细与版本比较.

任务已被服务器接受后, 关闭客户端不会取消任务. 主动退出与单纯断线不同, 前者触发撤销策略. 任何客户端显示的“已批准”都必须以服务端记录为准.

## 6. 验收方式

必须分别测试两个 Windows 用户、伪造工号、过期会话、用户退出、跨机器会话和 Linux 页面认证. 所有验证仅使用获准测试账号, 证据保存状态码、时间、目标与脱敏身份, 不保存密码或原始 Token.
